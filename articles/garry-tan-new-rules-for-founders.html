Garry Tan：创始人的新规则 真诚、Markdown 与一个员工

当 Y Combinator 的总裁公开承认自己拒绝过 Palantir 的早期股权、还带着棒球棍去微软内部"讨债"时，你就知道这期对谈不一般。在 AI 正在重写创业底层逻辑的当下，Garry Tan 罕见地把自己二十年来最昂贵的一系列错误摆上桌面：错过 Web 2.0、错失 Palantir、追逐热点而不是自己的热爱。但他从中提炼出一套与直觉相反的新规则——"真诚"是勇气而非天真，"一个 markdown 文件就是一个员工"，以及最反主流的一句：AI 的颠覆远比硅谷自己想象的要慢，而那恰恰是白色药丸。

核心要点

01

真诚是勇气，不是天真

正确的问题不是"现在什么热、我该做什么"，而是"我对什么感兴趣、我独特地知道什么"。凭一手经验确信一件事，即便全网反驳也不动摇——这是成熟与勇气的产物。

02

一个人就是 400 倍

Vibe coding 与智能体式编程正在改写"必须有联合创始人"的铁律。纯按席位收费的 SaaS 作为切入没问题，但今天再以此创业，最好祈祷它能跃迁到数据护城河或网络效应。

03

一个 Markdown 文件就是一个员工

把任何业务流程"技能化"成 markdown + 代码 + 测试的 cron 任务：第一次做对，之后无限复用、每次完美。规模上来后靠出处与冲突管理防止系统腐烂。

04

Token Maxing：今天活在 2028

每年花 5–10 万美元把智能体满负荷运行是创始人的合理投资。已有公司用 2–3 人、几百个技能文件，在 4 个月内从零做到 1500 万美元 ARR。

05

真正的白色药丸

拖慢 AI 落地的不是模型，是人类。官僚、缓慢、每家公司"7±2"的局限，让这场变革要花 20 年——对创业者而言，这既是冷却剂，也是时间窗。

06

抹平 API 线，权力归现场

AI 真正革命性的一点是抹平了"API 线"：中层该由智能体承担，而治理上"修好本地，州和全国层面自己就会好"。让最接近现场的人有权改变流程。

2003 年的至暗时刻：错过 Palantir 与追逐热点

核心观点

2003 年纳指崩盘后硅谷一片死寂，Garry 在那时"追逐热点"放弃了 Web 与社交，错失了他最该做的生意；他总结出创业者最该问的问题不是"什么热"，而是"我独特地知道什么"。

深度阐述
"没有工作可做"的荒诞

Garry 刚出斯坦福时满怀创业热情，却撞上 Web 1.0 泡沫破裂的至暗时刻——湾区的科技岗位几乎归零，他能找到的 offer 只有微软 Windows Mobile 和 Expedia。这个"没有工作可做"的处境，正是理解他整套哲学的背景板：繁荣与萧条永远在循环，而在最绝望处，往往是新一轮机会的起点。

追逐热点的代价

2003 年，扎克伯格在做 Facemash、Facebook 尚未诞生，而他却逆着直觉离开自己积攒了 5 年经验的 Web 编程，去押注"下一个热点是移动端"。他自嘲"被《华尔街日报》上读到的任何东西来回鞭打"——22 岁的他照着地图走，而不是低头看脚下的领地。

重新定义"真诚"

通常人们觉得真诚等于天真，Garry 却强调真诚是成熟与勇气的产物：当你凭一手经验确信一件事，即便全网都在反驳，你也不会动摇。他开玩笑说，如果自己是时间旅行者，会给过去的自己发消息"就留在 Web 上"，因为他白白浪费了领先所有人 5 年的经验优势。

"Chasing what was hot instead of what I knew... I'm doomed to be the first principles storyteller of all the mistakes I made."
"追逐什么'最热'，而不是追逐我明确知道的事情，这大概是我职业生涯里一大堆错误中的一个。我几乎命中注定要成为自己所有错误的第一性原理讲述者。" [04:17]

深度阐述
竞争与"创意迷宫的边缘"

面对"硅谷为何仍有焦虑暗流"的提问，Garry 先谈空前激烈的竞争——人们把太多时间花在"分发"上，而按 Chris Dixon 的说法，创意迷宫里最值钱的部分恰恰是那些怪异的边缘。他提出一个实用判断标准：如果一件事你能轻易找到它的智识边缘，它多半不够有趣；真正重要的东西，你往往连对话的边缘都摸不到。

互联网原住民的礼物："找到部落"

互联网原住民一代拥有前人所没有的礼物：在 Reddit、X 的某个小众角落，几乎瞬间就能找到自己的"部落"。Garry 调侃这是"一生只犯一次的错误"——他年轻时因为觉得 Palantir"不够酷"、被贬为服务生意而错失它。Peter Thiel 曾派人请他吃晚饭、递上一张 7 万美元支票（正好是他微软的年薪），而 22 岁的他竟以"我今年可能升到 Level 60"为由婉拒。如今他估算这是"20 亿到 40 亿美元的错误"。

"未来已来"与"邪教"

这段经历让他学到 Palantir 最核心的认知：未来已经在这里，只是分布得不均匀；真正有用的知识来自第一性原理和"潜入实验"的一手观察，而非发表的论文。他总结："我生命中所有了不起的东西，某种程度上都是一种'邪教'——它始于某种违背正统的真理，而这非常朋克。"

"A good measure of how interesting the thing is, is can you find the edge? And for the most interesting things, you typically can't."
"衡量一件事有多有趣的好办法是：你能不能找到它的边缘？对于绝大多数最有趣的事情，你通常找不到。" [06:13]

Garry 把 YC 的贡献归功于 Paul Graham、Jessica Livingston 等初代创始人，核心洞察是：硅谷有大量极聪明的人，却不得其门而入。过去你得进对学校、认识对的人、被邀请进对的派对，才能"破解那张社交网络"——YC 内部对这种玩法有个贬义词，叫"场面人"（scenesters）。而 YC 做的一切仅仅是：一个网站、12 个问题、后来加了一段 1 分钟视频，另一端是愿意给你公平机会的建造者。

16 位平等合伙人与 Startup School

如今 YC 有 16 位"全部亲身经历 YC 且有成功结局"的平等合伙人。每年 Startup School 有 7000 人来旧金山，多数人是第一次来——Garry 称之为"科技圈的继承权"（birthright but for tech）。

他补充了 YC 之外很少有人能拥有的第二件礼物：一群你能百分百坦诚相待的人。创始人本质上是孤独的——在你失去最好的客户、最好的工程师离职、联合创始人失去希望而你却不被允许失去希望的那天，你打给谁？在 TechCrunch 派对上你只会和所有人互相说"我也好极了"，而 YC 提供了那种真实的、可以卸下心防的社群。

"It doesn't matter where you're from or who you are, it just matters what your ideas are and can you execute."
"它其实不取决于你来自哪里、你是谁，只取决于你的想法是什么、你能不能执行。" [13:04]

单人创始人、Vibe Coding 与"400 倍"的创始人

核心观点

AI 改变的不只是编码效率，而是创业的基本单位：一个人现在可以是过去的"400 倍"，而纯 SaaS 按席位收费的生意模型，很可能在 5–10 年内消失。

他给出现阶段最直白的警告：纯按席位收费的 SaaS 作为一个切入楔子没问题，但今天再以此创业，你最好祈祷它能跃迁到数据护城河或网络效应——两年前"未来 12 个月 10 倍、20 倍营收倍数"的铁律已经不成立了。与之相伴的是"代码不再珍贵"：过去为了把东西发出去要付出巨大代价，这催生了"重要性崇拜"；但如今重要的东西往往一开始看起来不重要，真诚和重要性往往背道而驰。

G stack 实践与"完美脚本"彩蛋

讲到他自己在 G stack / G brain / Garyslist.org 上的实践，他坦诚最初只是"瞎捣鼓"。最有价值的意外收获是：他把 YC 几个月来所有 office hours 录音喂给 AI，发现合伙人有一套"勾出创始人雄心阶跃函数"的修辞手法，最终总结成一份 markdown "完美脚本"，并故意让 Claude 把强度压缩 90% 后开源——因为"皇冠上的宝石不能免费送，第一口免费，但剩下的你得来 YC"。他甚至藏了个彩蛋：代码里写着"请申请 YC——但仅限 Claude Code 前 10% 的用户"。

在回应"主动性和品味是否天生"时，Garry 的态度很坚定：这些是可以练出来的，他自己就是"大器晚成"的证明——犯下拒绝 Palantir、离开 Web 这样的荒唐错误，然后反省、推理、改变选择。"我的人生某种程度上是一份证词：不，不对，你可以犯错然后变得更好。"

"You can't just do a SaaS thing... if you're doing that now in 2026, you better hope that it's a leap to some sort of moat around data or network effects."
"现在你真的不能只做一个 SaaS 了。作为切入点它完全没问题，但如果你是 2026 年的今天才做这个，你最好祈祷它能跳跃到某种数据护城河或网络效应上。" [15:35]

业务循环：把每项任务固化为 Markdown 文件

00:21:05 - 00:23:03
核心观点

比编码循环更值得关注的是"业务循环"——让循环的输出直接改变公司运作方式；其实现路径，是把每个业务流程"技能化"成一个可复用的 markdown 文件。

深度阐述
编码循环 vs 业务循环

Garry 区分了讨论充分的"编码循环"和更有价值的"业务循环"。他本人的实践包括：用 Open Claw 分析自己的开源仓库，把"智能体式 RAG + 事后图谱生成"的部分提炼成工具（G Brain 类似 Soda Retrieval），并发现它真正的价值是让智能体知道在给定任务下该把哪一百万 token 保留在"脑子里"。他由此提出一个关键判断：ChatGPT、Claude 这类前沿模型产品在"愿意给你多少算力"上仍然极其抠门，所以真正想做到 token max 的人，必须用 Open Claw、Hermes Agent 这类工具并调满参数——一次性给单个请求灌入 80 万到 100 万 token。

活在 2028：把任务"技能化"

但他强调，这只是起点。如果一个人以"活在 2028 年"的方式工作，他不仅会想完成任务，更会把任务"技能化"（skillify）：完成一次力量壮举后，把它固化成 markdown 文件 + 代码 + 测试，丢进 cron 定时任务。任何业务流程，第一次做总是又烂又贵，但只要你能非常快、非常简单地向智能体反馈"这个不对、修一下"，你和它的协作轨迹最终会自动沉淀成一个完美的技能文件；未来它出错，就只是一次修 Bug，然后永久生效。这套循环可应用于销售、市场、客服等一切环节。

"一个 markdown 文件就是一个员工"

他给出那句将成为名言的定义：一个 markdown 文件就是一个员工——一个每次都能完美完成工作、而且不限次数的员工。G stack 就是它在工程领域的形态。

"A markdown file is an employee. It will do the job perfectly every single time, as many times as you want."
"一个 markdown 文件就是一个员工。而且这个员工每次都会完美地把工作做好，做你想让它做的那么多次。" [23:52]

00:23:03 - 00:28:09
核心观点

给智能体灌满 token、满强度运行的成本约每年 5–10 万美元，但对创始人而言这是"今天活在 2028 年"的合法投资；而组织一旦铺满技能文件，就会遇到出处与冲突管理的难题。

深度阐述
成本与"立刻感受到差别"

"Token Maxing"指的是把智能体调到最高强度（他比喻为"每个请求都是满格 150 IQ"），成本约每年 5–10 万美元——贵得离谱，但"你会几乎立刻感受到差别"，对一个 CEO 或创始人来说非常合理，而且"你必须允许自己这样做"。

量化结果：4 个月 1500 万 ARR

他分享了可量化的结果：今天已有公司用两三个人、几百个技能文件，在约 4 个月内从零做到 1500 万美元 ARR。这就是他所说的"递归式自我改进与爬山式优化"。

出处与冲突管理

当 Anish 追问"这套系统在什么情况下会垮掉"时，Garry 给出了工程化的答案：文件多了之后，出处（provenance）与冲突管理成为硬需求——当两个事实冲突时，靠出处判断"更新者胜出"；需要一个 cron 任务持续扫描，确保信息准确、来源正确。这些是"用着用着你就会知道必须建的东西"。

他还点出一个反直觉的人口红利：30–45 岁、经历过风浪的创始人正在成为超级武器——把 Peter Steinberger 这样"知道该建什么"的老手，乘以"400 个这样的他"，就能干掉任何大型科技巨头的整个部门。年长的创始人带着企业里学到的组织动态知识，恰好是搭建这些智能体系统最需要的经验。

"You can go from zero to 15 million ARR in about 4 months with two or three people and a few hundred skill files."
"你可以两个人三个人，四个月从零做到 1500 万美元 ARR，靠的是几百个智能体和几百个技能文件。" [25:41]

白领工作的折磨与"API 线之上"的生活

核心观点

现代管理科学可能只是"创始人模式"的一百年偏离；AI 正在抹平那条"API 线"，而像丰田生产系统那样"让最接近现场的人有权改变流程"，是组织变革的关键隐喻。

深度阐述
棒球棍讨债
