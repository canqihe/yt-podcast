深度洞察

01

双重北极星与平台哲学

00:01:49 — 00:03:56
核心观点

Anthropic 平台团队同时服务于内部和外部两类用户，催生了独特的"双北极星"——内部追求极致速度，外部致力于赋能开发者构建任何产品。

深度阐述
内部北极星：速度优先

Katelyn 和 Angela 领导的平台团队扮演双重角色：对外是开发者构建 AI 应用的 API 层，对内是 Claude 自身产品的底层基础设施。在内部，他们追求的是"让产品团队能够以最快速度交付接近 AGI 级别的产品"——当你自己就是最新模型的第一手用户时，内部平台的效率直接决定了产品迭代的速度。

外部北极星：赋能构建

在外部，北极星更加复杂但方向一致：给予任何开发者所需的工具，让他们能与 Claude 一起构建任何想要的产品。这意味着 Anthropic 会深度嵌入到开发者的业务场景中去——与 AWS、Google Cloud 等云服务商深度集成，创造大量"基础模块"（primitives），让开发者能够以他们自己的方式表达产品。Angela 提出了一个深刻观点：在 AI 新世界里，过去经济上不可行的"最后一英里定制软件"，现在理论上变得触手可及。

基础模块与标准

这些基础模块有时以 API 和高级抽象的形式出现，有时则体现为标准本身——比如 Skills 和 MCP（Model Context Protocol）。"这些东西 Claude 本身就依赖它们来发挥价值，我们可以把它们开放给整个生态系统。"

"We want people to be able to express what they think their product should be. They want to be able to almost do custom software in their own way." — Angela Jiang [00:02:58]

"我们希望人们能够表达他们认为自己的产品应该是什么样子，能够以他们自己的方式做定制软件。"
02

什么应该外部化

00:03:54 — 00:06:02
核心观点

模型能力在指数级增长，没有谁能准确预判最终的"形态因子"。最好的策略是构建一个强大的平台，让市场自己涌现出答案。

深度阐述
对等性哲学

Angela 阐述了"什么放进平台、什么外部化"的核心哲学。许多平台企业会将内部和外部基础设施故意 bifurcate（分叉），但 Anthropic 选择了相反的方向：刻意保持两者对等。背后的核心论点是模型能力的指数级增长使得任何固定的形态因子都可能迅速过时。

形态因子的不确定性

"两年前我们还在说'一切都是聊天'，现在大家都说'别管聊天了，智能体才是未来'。"在这种持续演进中，最好的策略不是押注某个具体形态，而是构建足够稳健的平台，给人们发现形态因子的工具。

避免偏向陷阱

Katelyn 补充了关键陷阱：不要过度偏向内部用户的需求。内部用户有非常特定的需求（比如对原生速度的追求），外部用户也一样。过度偏向任何一方都会导致产品走偏。因此他们的做法是：内部吃狗粮（dogfooding）和外部早期接入同步进行，让两边的反馈同时进入平台改进循环。

"The capabilities of these models have just grown exponentially and it's really hard to figure out a long-lasting form factor." — Angela Jiang [00:04:29]

"模型能力在指数级增长，很难找到一个长期有效的形态因子。"
03

从消息 API 到智能体

00:06:00 — 00:09:08
核心观点

一年前平台就是 Messages API，现在已进化到能够提供开箱即用的智能体能力，客户分化明显：AI 原生公司用基础模块，传统企业用托管方案。

深度阐述
进化轨迹

Katelyn 描述了平台进化：她加入时平台基本上只有一个 Messages API——无状态的 API，加上 SDK、文档和 MCP 标准。但随着 Claude 的能力提升——能运行更长时间、处理更大上下文——客户和 Anthropic 内部都在做同一件事：构建能在长时间上下文中成功运行、甚至无需人工介入的智能体。

高阶抽象的诞生

他们意识到，可以将内部搭建过的那些基础设施——沙箱管理、权限治理、会话存储等——打包成高阶抽象，提供给外部开发者。"开箱即用的智能体能力"成为了平台的新方向。

客户选择的分化

AI 原生创业公司倾向于直接操作底层基础模块，追求最大灵活性；而传统企业或非 AI 核心业务的公司，则更倾向于选择"托管智能体"（Managed Agents）这种一体化方案——"这不是他们的核心能力，也不是他们想投入资源的地方"。

"We found that we could piece together our primitives and stand up all the same infrastructure that we're finding ourselves standing up internally to power our own products and arrive at some higher order abstractions." — Katelyn Lesse [00:06:59]

"我们发现可以把基础模块组合起来，搭建起我们内部用来驱动自家产品的那些基础设施，从而提供更高阶的抽象。"
04

三层蛋糕：知识、执行与协调

00:09:07 — 00:12:13
核心观点

平台抽象为三层架构：知识层（最成熟）→ 执行层（投入最多）→ 协调层（最前沿）。真正的创新在元层面——"策略"系统赋予 token 不同工作。

深度阐述
知识层（Knowledge Layer）

最底层，也是最成熟的一层。它回答的是"如何用 Claude 做事情"。抽象包括：Messages API 上精心设计的参数形状（以彰显 Claude 的思考方式）、工具调用的标准化、Skills 和 Memory 等上下文机制。这些在过去一年多已经逐步推出并不断演进。

执行层（Execution Layer）

当前投入最多的领域。知道和做是两回事——"我可以问它一个问题得到一个答案，但如果你需要它执行——编辑文件、操作多个系统——那就复杂得多了。"包含底层框架加托管基础设施，代表产品是 Claude Managed Agents。

协调层（Coordination Layer）

最前沿的方向。核心概念是"策略"（Strategies）——一种"元框架"。解决 token 分工问题："如果 token 不是可互换的，需要给不同 token 不同的工作——这个 token 负责建议，那个负责执行，这个负责反思，那个负责执行——你就要开始组合这些编排策略。"

"The true low-level harness is designed for execution. But the next one is about… if tokens aren't really fungible and you need to give them different jobs." — Angela Jiang

"真正的底层框架是为执行设计的。但下一层是关于：如果 token 不是可互换的，你需要赋予它们不同的工作。"
05

开放生态而非围墙花园

00:12:13 — 00:17:12
核心观点

Anthropic 不执着于掌控整个技术栈。电力之所以变革，是因为每个人都能接入——这是开放生态的核心理念。

深度阐述
电力比喻

Angela 用了一个精彩的比喻来阐述他们的生态系统理念——电力。电力之所以成为变革性的公用事业，不是因为某一家公司垄断了它，而是因为"每个人都能接入，你有标准和方式来接入所有需要的部分。这不是任何一个人能独自完成的。"

三件核心事

第一，提供尽可能全面的基础模块（知识层+执行层+协调层），让开发者可以自由组合；第二，建立使不同智能体能够互操作的标准——基于 MCP 规范的连接器（connectors），让 Claude 智能体和非 Claude 智能体都能协同工作；第三，推动安全层面的互操作性——"没有人希望自己的服务上运行着做坏事的技术"。

执行层面的开放性

Katelyn 展示了这种开放性的具体体现：自托管沙箱——与 Modal、Vercel、Cloudflare、甚至亚马逊的 microVM 合作，"是否运行在我们的基础设施上对我们来说并不重要"。真正重要的是"你构建这些智能体的架构是否正确、是否强大、是否可靠和可扩展"。

"Whether it runs on our infrastructure versus somebody else's infrastructure is actually not important to us because the thing that's important to us is more that the architecture of how you put together these agents… is powerful." — Katelyn Lesse [00:16:36]

"是否运行在我们的基础设施上还是别人的基础设施上，对我们来说并不重要。对我们重要的是：你构建这些智能体的架构是否正确、是否强大。"
06

垂直产品与形态因子探索

00:17:12 — 00:22:27
核心观点

选择垂直领域的两个原则：展示新形态因子的可能性，聚焦于"token 饥饿型"的迭代式工作流。

深度阐述
形态因子是动态的

"今年很棒的 AI 产品形态，明年可能就不行了。"Anthropic 内部有一种文化：做一个东西，流行一年，然后可能就不是下一件该做的事了——那就扔掉，重新尝试。Claude Design 就是例子：它的真正创新在于表达两件事——第一，你可以把越来越多的事情交给 Claude；第二，代码本身就是一种设计工具。

token 饥饿型领域

衡量标准是：完成一次交互后，你是觉得"完成了"还是"太棒了，我还想做得更多"？编程显然属于后者——一次成功的代码生成解锁了更多的构建欲。这与其他一次性任务形成鲜明对比。

垂直化尝试

在金融、法律等领域进行垂直化尝试，目标是展示"可能性之艺术"——在 Messages API、Managed Agents、连接器插件等不同接入方式上的多样性实验。

"We actually don't think form factors are static. What might be awesome for one year's worth of AI development will probably not be awesome for the next year's worth." — Angela Jiang [00:17:12]

"我们不认为形态因子是静态的。今年很棒的 AI 开发方式，明年可能就不行了。"
07

Claude Tag 的真正价值

00:22:26 — 00:26:04
核心观点

Claude Tag 的本质不是"Slack 机器人"——真正的创新在于引擎盖下的上下文工程、主动性和"组织级框架"架构。

深度阐述
界面只是冰山一角

"是的，你与它交互的方式就是在 Slack 中 @它。但那只是界面，不是重要的部分。"重要的是引擎盖下的三层创新。

上下文工程

Claude Tag 能主动理解一个团队的上下文——它知道谁在做什么、什么信息对谁有用。无需 @它也能主动提供帮助。

主动性（proactivity）

传统工具是被动的——你问它才答。Tag 设计成"it just gets stuff done for you"——像一个真正的同事。

组织级框架

Andrej Karpathy 的概念很精准——Tag 是一个为整个组织设计的框架，不是在单一任务层面优化，而是在组织协同层面优化。Angela 认为 Tag 展示了未来的方向：智能体将采用人类已经采用的形态因子。

"It's like an iceberg — all the stuff underneath it that's actually becoming harder and harder and like the useful part… The interface can actually constantly swap." — Angela Jiang [00:24:52]

"它像一座冰山——水面下所有东西变得越来越难、越来越有用。而界面本身可以不断切换。"
08

框架工程的最佳实践

00:26:04 — 00:38:15
核心观点

未来的框架创新不在底层（提示词缓存、上下文窗口清理），而在元层面的"策略工程"——如何赋予不同 token 不同"工作"。

深度阐述
当前最佳实践

提示词缓存（prompt caching）——"一定要做，你会节省大量 token 成本"；保持上下文窗口清洁；建立可靠的评估（evals）体系。但她们认为底层优化的"油水"已经快榨干了。

模型的可引导性革命

Angela 提出了关键洞察：两年前的框架需要大量脚手架——"你必须建一堵墙在这里，一堵墙在那里，让东西沿着直线走。"而现在模型本身已经非常可引导（steerable）——你只需要在提示词里说"去从 A 到 B"，模型就会照做。这意味着那些引导型的框架代码可以直接删掉。

领域特定性

Angela 认为不存在通用的"完美框架"。真正的差异化在于模型与外部系统之间的验证逻辑——在法律、金融等高后果领域，那点验证逻辑上的差异可能决定产品成败。

元框架与"赋予 token 工作"

不只是让模型执行，而是让某些 token 去反思过去的智能体会话并将经验写入记忆，让大模型去建议让小模型去执行，让评审 token 去检查执行结果——"做得好吗？没做好，再试一次。"这种"策略"层面的创新将提供比底层优化更大的杠杆。

来自客户的创新

有客户在 Claude Managed Agents 上构建了智能体，在其他模型上也构建了智能体，然后通过在智能体上暴露 MCP 服务器，让一个智能体调用另一个智能体的工具——实现了跨平台智能体的模块化协作。这是目前最令人兴奋的创新领域之一。

"The interesting innovation is going to come more at that higher level — on the meta level. Optimizing within those strategies is something our team is really excited about." — Katelyn Lesse [00:28:15]

"有趣的创新将越来越多地发生在元层面。在这些策略内部进行优化是我们团队非常兴奋的事情。"
09

Token 成本与理性化时代

00:38:13 — 00:43:39
核心观点

"Token 最大化"之后迎来"Token 理性化"。正确策略是构建智能的"复杂度路由"——对不同难度任务分配不同成本模型，而非设上限停止使用。

深度阐述
自然周期

Angela 用"Token 最大化→Token 理性化"这个框架来概括当前行业正在经历的自然周期。"随着模型越来越强大，你经历了智能最大化阶段，然后下一个维度要么是成本，要么是速度。"

危险现象

有些公司面对 AI 支出爆发（通常通过影子 IT 的方式），第一反应是"设一个上限"。这是错误的——"不要停止创新。如果你从中获得了回报，交付更快，运营更高效，这些就是收益。"

智能路由策略

正确做法是对任务进行复杂度评估——难任务路由到大型智能模型（如 Opus），简单任务路由到更便宜的模型。虽然路由器的技术复杂性不低，但它是可行的，而且正是平台应该帮助用户解决的问题。

模型特异性观点

Katelyn 坦率地表示，Anthropic 对"跨模型路由"不感兴趣——"我们是专为 Claude 设计平台的"。这不是垄断心态，而是一个工程判断：框架的优化与模型的行为特征紧密相关，最优解来自于深度绑定而非通用抽象。这意味着未来可能是"不同模型家族各自有自己的智能体框架，框架之间通过标准协议互操作"的局面。

"We have a strong belief that harnesses and the agentic layer should be tuned to the model family that you use it with." — Katelyn Lesse [00:41:11]

"我们坚信：框架和智能体层应该与它所使用的模型家族进行调优。"
10

未来方向："可组合策略"

00:43:37 — 00:48:03
核心观点

Anthropic 平台接下来的重点是可组合策略（composable strategies）——让开发者能以简单方式编排"最佳 N 选一"、"监督执行"等高级智能体架构。

深度阐述
未满足的巨大需求

开发者知道"最佳 N 选一"（best-of-N）可以提升效果，但构建和运行这样一个系统并将其投入生产"非常非常困难"。大多数人只有两个杠杆——换更大的模型或者让模型跑更长时间——但第三个杠杆（策略级优化）往往更有效却难以触及。

平台的使命

"这很难。所以按我们一开始的哲学：如果它能给你想要的回报，而且它很难，我们就努力让它变得简单。"她设想的未来是：平台提供多个预设的"工作类型"（job types），开发者可以像搭积木一样组合它们。

两个必须同时推进的方向

一是企业级就绪——安全、合规、权限控制，这些都是让大企业说"好的，这个对我可行"的前提；二是更开放的开发者体验——让"周末开发者"也能轻松接入并构建有趣的东西。只有解决这些基础问题，才能真正解锁平台的创新潜力。

"We can give you like five jobs off the top of our head — that's what we have internally. And if we give this out to the rest of the ecosystem, there's probably going to be like 100,000, 200,000… who knows what other combinations people could put together." — Angela Jiang [00:46:10]

"我们可以给你五个现成的工作类型——这是我们现在内部有的。如果我们把这个交给生态系统，可能会产生 10 万、20 万种不同的组合。"

精华收获

🏗️

三层框架

知识→执行→协调的三层模型是理解 Anthropic 平台战略的最佳框架。真正的创新杠杆在最高层——"赋予 token 不同工作"的策略层，而非底层的缓存或上下文管理。

🔌

开放为锚

开放生态不是意识形态，而是务实判断：「电力之所以变革，是因为每个人都能接入。」与 Modal、Vercel、Cloudflare 的合作、MCP 标准的开源、自托管沙箱——都是这一锚定理念的落地。

🎯

模型特异性

「框架应该与模型家族绑定」——这既是技术判断也是战略选择。长期来看，这会创造一个"每套模型家族+自有框架+开放协议"的竞争格局。

🔄

形态因子永远在变

「今年很棒的 AI 产品形态，明年可能就不行了。」平台的核心价值不在于押注某个形态，而在于提供足够灵活的抽象层，让形态从市场中自然涌现。

⚡

三个杠杆

大多数人只使用两个杠杆（模型大小、运行时长），却忽略了最有潜力的第三个：策略级优化——"最佳 N 选一"、反思-执行分离、大模型建议小模型执行等组合策略。

🚫

不要设上限

Token 理性化的正确方式不是限制 AI 使用，而是构建复杂度路由——「给它一个任务评估复杂度，难的任务找大模型，简单的找便宜模型。」创新不能被预算上限扼杀。

核心理念

Anthropic 的平台哲学可以用一句话概括——

"我们并不执着于工作负载运行在谁的基础设施上，我们只关心架构是否健全。"
