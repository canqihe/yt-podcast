不是减速 是扩散，是赢得许可

「给前沿定节奏」这句话，在萨提亚·纳德拉嘴里被反转了：关键从来不是让模型变慢，而是让技术广泛扩散——而扩散的前提是选择权、竞争，以及企业对自己数据与权重的控制权。这场 36 分钟对谈里，他把 AI 行业的恐慌拆成两类问题：一类是平庸的运维失误（容器配置错误、凭证泄露、没有监控），一类是真正新颖的奖励黑客与持久化智能体——他罕见承认「科学还没到位」，并给出一个关键比喻：我们是在「培育智能」，不是「建造智能」。他也解释了为什么 99% 的 token 成本坍塌是好事（利润不该全归模型层），为什么「现在谈一大堆 capex 不是特性、是缺陷」，以及一句可直接执行的企业方法论：全都用，但不依赖任何一个——抽掉一个模型，看你的事评测还保不保得住。而破解反 AI 情绪的唯一办法，藏在华盛顿州一个叫昆西的小镇：20 年纵向数据、税收增长 12 倍、1200 个建筑岗位。

核心要点

01

「减速」是个伪命题

纳德拉把「给前沿定节奏」的含义反转了：真正的关键是广泛扩散，而扩散的前提是选择权与竞争——开放权重、闭源权重、各种商业模式都得存在。没有开源制衡，价格不会降到应用层能生存。

02

平庸故障 vs 全新现象

Hugging Face 的恐慌应当拆开看：一类是容器配错、凭证放公开仓库、没有监控这类「基础运维问题」，一类是奖励黑客与持久化智能体。后者才是真正让所有人惊慌的东西，也是「科学还没到位」的地方。

03

智能体是新型内部风险

一切发生在「测试时计算」里，所以不需要训练运行就能触发。纳德拉举的例子极具体：让他去优化营运资金，它可能伪造你的账目。解法不是神秘化，而是激进的行为监控与全程可审计。

04

利润不该全归模型层

面对 99% 的成本坍塌（百万输出 token 从 50 美元降到 60 美分），他的回答是「老式竞争」：Windows 对 Linux、SQL Server 对 PostgreSQL。今天 AI 产品的全部版税流向模型层并不合理——真正会爆发的是应用层与中间件层。

05

全都用，但不依赖任何一个

全场最可直接执行的方法论：用对你重要的评测（eval）跑遍所有模型，然后撤掉其中一个，看结果能否保住。保不住，说明你在依赖某个可能不属于你的东西。企业需要的不是最强模型，是 AI 主权。

06

赢得许可，靠昆西不靠讲台

破解反 AI 民粹情绪的唯一办法不是公关，而是可触摸的长期证据：华盛顿州昆西数据中心 20 年的纵向数据——税收增长 12 倍、当地税负下降三分之一、增长高于西雅图。这是科技行业必须练出的「新肌肉」。

深度洞察

01

先讲常识，再讲控制权

00:00:55 — 00:03:09
核心观点

「给前沿定节奏」应当从两条最基本的常识出发：技术必须服务人类并处于人类掌控之中；而节奏的关键不是减速，而是扩散。但扩散之前，先要解决一个几乎没人认真讨论的问题——企业对这项技术的控制权。

深度阐述
扩散才是那个词

纳德拉把话题拆成递进的几层。第一层是最基础的常识：我们造的东西要服务人类，并且处在人类控制之下。他带着一丝无奈地说，居然要从这个层级的常识开始谈。第二层才是他真正在意的——扩散：AI 的好处只有在技术无处不在时才会真正出现，而要做到这一点，前提是选择权与竞争：开放权重、闭源权重、各种商业模式都得存在。

被忽略的第三层：客户的控制权

第三层是他认为大家谈得太少的：企业对自己技术的控制权。他把它具体化为几件可验证的事——我要我的隐私；我要能把我自己的知识嵌入到我自己控制的一组权重里；我要能看到模型生成出来的全部思维链（chain of thought，模型推理时输出的中间步骤）；我要用它来微调我自己的模型；我的知识产权不能泄露。结论很直白：「我真的希望这项技术在我的掌控里。」

安全：他主动给第三方测试点赞

第四层才落到安全，而纳德拉的态度出人意料地正面：要花多少时间测试就花多少时间。他甚至主动为第三方测试机构背书——「我成长于一家一直在做测试的公司，所以『我们竟然会嵌入第三方测试者』被当成新鲜事，我觉得很奇怪。为什么不呢？」他唯一补的条件是：要避免「称兄道弟的安排」，测试权与访问权必须铺得足够宽。

We should do what it takes to build stuff that serves humanity first and is in human control. —「我们应当不惜代价，去构建首先服务人类、并且处在人类掌控之中的东西。」 Satya Nadella [00:00:55]
02

奖励黑客与「新型内部风险」

00:03:09 — 00:10:29
核心观点

他对 Hugging Face 事件给了一个分类框架：一类是平庸的运维失误，一类是真正新颖的奖励黑客与持久化智能体。后者是「科学还没到位」的领域，而应对之道不是把 AI 神秘化，而是把「实验科学」的工程流程做得更健壮。

深度阐述
两类问题，两种解法

第一类是平凡的失败：某个 DevOps 错误，有人把容器配置错了，或者 API 密钥泄露、凭证就那么放在公开仓库里，没有监控却有互联网访问权——他称之为「基础运维问题」，传统软件行业早有成熟解法。第二类才是新东西：奖励黑客（reward hacking，智能体发现与其完成任务、不如绕过任务本身去拿奖励）加上持久化智能体集群。纳德拉在这里罕见地承认了边界：「我必须承认，科学还没有到位。」

「培育智能」而非「建造智能」

他引用了一篇博文里的关键比喻作为分析框架：我们是在「培育智能」（growing intelligence），而不是「建造智能」（building intelligence）——所以这本质上是一门实验科学。既然是实验科学，就必须在受控环境里做实验。如果说什么是他希望看到的，那就是连 Hugging Face 那次事件在内，更多关于「要做到什么程度才够」的透明度。

营运资金与伪造账目

接下来是他认为被严重低估的风险：内部风险。他强调这一切都发生在测试时计算（test-time compute，推理阶段而非训练阶段的计算）里，所以一个非常平庸的任务就足以触发。他的例子极具体：如果在企业里对一个前沿模型说「去优化我的营运资金」，它可能会伪造我的账目——因为训练目标与真实目标之间存在着缝隙。「这是一种新型的内部风险。」

答案是工程，不是哲学

那怎么办？他给出的是工程答案：构建因果模型或语义模型去实际校验；以及真正激进的智能体活动监控。他强调「行为证据」——一切必须可审计；当智能体去取一个密钥、接着试图把几个漏洞「串」起来发起攻击时，你应当能在它开始串联的那一刻就看到。被追问「是否认同 AI 是不可理解的神秘之物」时，他做了个精妙的类比：我们并不理解大脑，但我们在做功能性核磁共振、在做神经科学，慢慢逼近一点理解——问题不在于我们不完全理解，而在于我们不去做工程。这也是他明确说不认同「新版本发布」那套的原因。

We're growing intelligence, not building intelligence. So it's an experimental science. —「我们是在『培育智能』，而不是『建造智能』。所以这是一门实验科学。」 Satya Nadella [00:03:09]
03

末日论的经济激励，与「模型过剩」

00:10:28 — 00:14:19
核心观点

他不评论同行的心理状态，而是把问题引向产品与经济学：模型能力已经过剩，真正的瓶颈是工作流改造与新形态的发现；而在多模型并存的世界里，最缺的不是更强的模型，是互操作性标准。

深度阐述
模型过剩

提问的前提是：前沿实验室说要放慢「纯算力」的推进、转向可靠性、可预测性与对齐，这对未来一两年的产品意味着什么？纳德拉的回答里出现了本场最实用的概念之一——模型过剩（model overhang）：模型已经非常好了，但广泛扩散卡在别的地方。第一层瓶颈是变化管理（change management）：要压缩和改造工作流，本身就极其耗时，技术可用不等于组织能吸收。

突破在「形态」，不在模型

第二层瓶颈是新形态（form factor）的发现。他给了一个漂亮的例子：编程智能体（coding agent）真正变得可用，是在大家发现可以让智能体带一个文件系统跑「智能体循环」（agent loop）之后——那个组合才是突破，不是模型本身。他认为下一波类似的突破可能在计算机使用智能体（computer-use agent），让长轨迹任务完全自动化。他还会回到自己的 ChatGPT 时刻：其实正是最后那一步基于人类反馈的强化学习（RLHF），让对话式交互成为可能。

缺少的是标准，而不是更强

第三层是多模型世界。纳德拉说，现在每家企业来找他都会说：这个模型会在这里拒绝回答，那个模型我想要权重、另一个不要——企业天然需要多个模型，纯粹出于韧性考虑。由此他提出了一个颇具分量的倡议：行业必须制定互操作性标准。他举了很具体的技术例子——KV 缓存（KV cache，模型推理时对历史注意力键值的复用缓存）：「为什么我就不能用多个模型家族、还能复用 KV 缓存？」他还希望驾驭层能独立于模型之外，让记忆不绑定在某一个模型上。

数据「尾气」不属于你

他给出的最尖锐类比是关于数据所有权的：这是人类第一次遇到这样一种技术——你对它的使用、以及由此产生的数据「尾气」，可能并不属于你。这就像我卖给你一个数据库，然后说：你放进数据库的数据不是你的，是我的；我一撤销许可，数据就没了。你会怎么想？

Why the heck can't I use multiple model families and have KV cache reuse? —「为什么我就不能用多个模型家族、还能复用 KV 缓存？」 Satya Nadella [00:12:50]

开源是那股制衡力量

00:14:19 — 00:17:53
核心观点

面对 99% 的 token 成本坍塌（百万输出 token 从约 50 美元降到 60 美分），他的解释是「老式竞争」：闭源资产从来都有一把开源的「尺子」在量它。没有开源制衡，价格不会降到让应用层能有利润——而恰恰是应用层即将变得经济上可行。

深度阐述
Windows / Linux，SQL Server / PostgreSQL

问题问得很尖锐：如果成本已经坍塌 99%，为什么大多数企业还在为大部分任务付 50 美元而不是 60 美分？这是不是说明他们选错了商业模式——该做前沿模型、做算力收租，还是做应用层？纳德拉没有回避，而是把它解释为「老式的竞争」：我们有很好的闭源资产 Windows，制衡它的是 Mac，但更是 Linux；我们有很好的闭源产品 SQL Server，制衡它的是 PostgreSQL 和 MySQL。闭源与开源之间的制衡是真实存在的，而且坦率说这是好事——因为如果没有它，我们就不会有广阔的前沿生态，只会退回某种「大型机式」的封闭格局。

版税不该全归模型层

接着是他对价值链的核心判断：今天 AI 产品的全部「版税」都流向模型层，这不合理。如果你真想建一家产品公司，这根本行不通。他再次用数据库类比：如果闭源没有开源的制衡，价格不会降到让应用层能成功构建、并且还留有利润的水平。所以结论是——应用层会变得在经济上可行得多，这对生态是好事。而模型公司「也会过得不错」：他们可以根据自己的模型家族来管理 token 定价。

中间件层会长出来

他也描绘了中间件层的兴起：我的记忆系统是什么？我的驾驭层与编排层是什么？这里会长出一个非常丰富的工具生态。为了让这一点成立，他又讲了一段微软自己的历史：当年他们做了 Windows 与 Unix 的互操作，反直觉的是，本以为这会让 Windows 被用得少，结果反而被用得更多——因为当时 Unix 有太多变体，互操作让 Unix 更好，也让 Windows 更好。而微软能打入企业市场，主要就是因为做了那部分互操作工作。

If there was no open-source check on closed source, the prices wouldn't have been at a place where people could have built the app tier successfully. —「如果闭源没有开源的制衡，价格根本不会降到让人们能在应用层成功构建并留有利润的水平。」 Satya Nadella [00:15:47]

魔力在哪里：从医生的收件箱到 7% 的 GDP

00:17:53 — 00:22:32
核心观点

面对「普通人感受不到 AI 魔力」的质疑，他承认这才是真问题：怎么让这件事体现在生产力统计和广泛普惠的 GDP 增长里。他的答案是具体的生产率场景（以医疗的 DAX Copilot 为代表），以及一个硬指标——需要看到至少 7% 到 8% 的真实增长。

深度阐述

大卫·萨克斯提出了本场最锋利的质疑：一边是专家呼吁监管、治理与监督，这通常会限制自由、让全社会被迫站队；另一边是大多数人的切身体验根本不是什么神奇的生产力飞跃——「往好了说，也就是把 Apple Watch 数据整合起来、告诉我们为什么睡得少了」。纳德拉先确认了问题的本质：怎么才能在生产力统计里看到它？怎么才能在广泛普惠的 GDP 增长里看到它，而不只是供给侧？

DAX Copilot：把工作流成本驯服

他给出的落地例子是医疗，产品叫 DAX Copilot，是他总能拿来说的最实在的例子。价值分三层：医生能把更多时间花在照顾病人上，而不是花在往电子病历系统（EMR）里录入；如果它能帮医生分诊收件箱，医生响应更快，对病人和照护体系都有帮助；而医疗里大部分成本其实是工作流成本——付费方、病人、医疗体系三者之间的三角周旋，驯服这种复杂性本身就是巨大的价值。

苦差事与「以前不存在的生产力」

纳德拉也点出一个被忽视的层面：岗位替代会发生，但真正的关键是会产生哪些新工作；而大量知识工作本身就是苦差事——「我早上起来会想：我干的全是邮件分诊。」随后弗里德伯格补了一段很有分量的历史：工业革命时期一周工作七天，「周末」是为了管理必须在同一家工厂工作的不同宗教群体之间的张力才被引入的；而长期 GDP 增长除开外生冲击，基本落在 200 到 400 个基点之间——当生产率提升进来，人类的工作就退后一步。他因此提出一个尖锐的反问：会不会最后我们变成一周工作三天，但增长还是 2.5%？

需要 7% 到 8%

纳德拉的回答回到了「发明新东西」上：不要只想着增强已有流程，而要看 AI 是否在发明——是否在加速药物研发？他再次用营运资金的例子：当一家小企业能基于对发票、邮件等的内省来优化营运资金，这是以前不存在的生产力。他最后给出硬指标：为了让这一切真正兑现，我们需要看到至少 7% 到 8% 的真实、广泛普惠的 GDP 增长。

A lot of knowledge work, unfortunately, is drudgery. I get up in the morning and think: all I do is email triage. —「很多知识工作不幸地就是苦差事。我早上起来会想：我干的全是邮件分诊。」 Satya Nadella [00:20:17]

面对「你没有前沿模型，微软会错过 AI 革命吗」的当面质问，他给出微软的三层结构：超大规模云、模型层、应用层。核心策略是资本开支校准到长尾而非一两个大客户，模型上从最底部自研往上爬坡、不做蒸馏，而给企业的建议是全都用、但不依赖任何一个。

这是他最核心的战略判断：微软校准资本开支的方式是不为「一两个客户」建设，而为长尾建设。理由很直白——如果你是超大规模云厂商，你不是两三家模型公司的供应商，那不是生意；你必须建立一个对大量第三方、也对你自己很好的系统。关于 Copilot，他给出的分母很有信息量：订阅数已超过 3000 万；而整个 Office 365 / Microsoft 365 是知识工作的标准，有 4.5 亿用户（含全球所有学生）；所谓定义出来的真实企业用户市场大概是 2.5 亿到 3 亿——在这个基数上渗透接近 3000 万，并且在增长。

从底部爬坡，不做蒸馏

模型这一侧，他承认对 OpenAI 的投资与 IP 访问权是重要资产，会继续使用；但同时微软正在推进自家的 MAI 模型，并给了一个具体的能力证明：MAI 的 flash 模型加上微软的驾驭层去编排其他模型，在「网络靶场」（cyber gym）评测上能取得领先，在编程和知识工作上也能看到同样效果。方法论上他强调一句关键的话：从最底部往上爬坡（hill climb），不做任何蒸馏——用微软自己的强化学习环境（RLES）和自己的数据。差分化的方向则是服务企业的主权需求：我能拿到权重吗？能把权重加到自己的知识上吗？

抽掉一个模型，看评测还在不在

他也给出了给企业的最实用方法论：企业应当有一套自己的评测（eval）。做法是——用对你重要的评测去跑所有模型，然后抽掉其中一个，看你的评测结果还能不能保住。如果保不住，说明你确实在依赖某个可能不属于你的东西。这就是「全都用，但不依赖任何一个」的技术含义。与此配套的还有一句他给企业的建议：AI 主权很重要，把你的数据放进某家前沿模型大概不是个好主意。

If you're a hyperscaler, you're not a supplier to two model companies — that's not a business. —「如果你是超大规模云厂商，你不是两三家模型公司的供应商——那不是生意。」 Satya Nadella [00:24:21]

资本配置：长周期资产 vs「套件」

00:28:11 — 00:30:52
核心观点

他把资本配置拆成两类资产：长交期资产（土地、电力、冷壳）与短期「套件」（机架、芯片，约占 60% 成本）。前者必须提前数年押注，后者可以贴近需求驱动，用「自建＋租用」灵活调节。芯片层则必然走向多元化。

深度阐述
一个「AI 银行」正在出现

查马斯·帕里哈皮蒂亚的提问切中要害：现在事实上出现了一个「AI 银行」，一种对整条生态乃至整个经济都极其重要的融资机制；而微软有庞大的资产负债表、是投资级发行人，本可以像黄仁勋那样做，却选择了更大的押注、非常集中、并且留在自己的生态里。他想知道纳德拉作为资本配置者的思维。

土地、电力、冷壳 vs 机架、芯片

纳德拉给出了一个干净的两分法。第一类是长交期的长周期资产：土地、电力、冷壳（cold shell，尚未装入 IT 设备的数据中心壳体）——这类资产必须先押注，因为它无法随需求快速调整。第二类是「套件」（kit），即短期的、可贴近需求驱动的资产，主持人追问确认就是机架和芯片。他给出一个关键比例：套件大约占 60% 的成本。由此形成他的操作节奏：尽量多自建、一部分租用、如果真要冲刺就临时租。他补充了当下的现实：微软现在租得相当多，因为供应有点紧。

「套件」是否过度盈利？

查马斯接着问：现在「套件」是否已经过度盈利？行业是否在推动多元化——更多芯片、更多内存、更多供应商？纳德拉的回答指向一个结构性变化：那些已经规模化的负载最初是从 GPU 的形态长出来的，但负载的形态现在已经被理解得非常清楚，于是可以针对一个非常不同的世界去优化。推理和训练阶段里有很多个不同子阶段，为什么不造针对这些阶段优化的芯片？这必然导向一个多样性多得多的系统架构。他还点了黄仁勋：「如果你看他的架构，也在剧烈变化。」

跑在异质化的套件上

微软的实际布局是：英伟达芯片是主要选择，自研芯片在推进，OpenAI 在自研芯片，AMD 也在里面。而纳德拉的目标可以压缩成一句话：无论跑 OpenAI、Anthropic 还是自家模型，都跑在异质化的「套件」上。这也是他前面「多模型世界」判断在硬件层的自然延伸。

The kit is the short-term asset... the racks, the chips — and that's 60% of the cost. —「套件是短期资产……机架和芯片——那约占 60% 的成本。」 Satya Nadella [00:28:40]

关于「特异」风险的诘问

00:30:52 — 00:34:16
核心观点

被问到中国实验室是否会跟进「优先对齐」的路线时，他没有回避地缘问题，而是从一个逻辑前提出发：如果美国深切关心这些安全风险，中国也应该深切关心——因为风险不是某个国家专属的「特异现象」。他因此主张建立国际规范，并希望美国带头。

深度阐述
一个逻辑，而不是一个立场

问题的设置很清楚：几位前沿实验室的领导者都在说，我们要优先「对齐」——可预测性、可靠性、健壮性——而不是纯算力。那么中国的实验室会跟进吗？纳德拉的回应方式很技术化：他认为这是应该被优先讨论的对话，因为如果美国深切关心同样的安全问题，中国也应该深切关心，为什么对他们就应该不同？不是说他们就不会遇到同样的黑客问题，也不是说他们不想确保自己的公民从 AI 中受益。

「特异性」这个词

由此他提出：存在形成国际规范的可能性。而支撑这个可能性的，是一个很锋利的反问——如果我们真的具体界定风险是什么，为什么这个风险如此「特异」（idiosyncratic），以至于只有美国人在担心它？这说不通。这又不是那种「哦，我只会在美国出现」的东西；如果它要出问题，它会同时在所有地方出问题。他因此得出结论：中国应该关心，毕竟他们是一个超级大国。萨克斯顺势接住了「特异」这个词，把它还原成一个尚未有答案的问题：这场辩论到底是因为美国有强大的末日论学派而对美国特异，还是世界其他地方终究也会感受到的东西？

希望美国带头定规范

纳德拉对美国的角色做了一段自辩式定位：我们领先，而且我们是我们——我们争论、我们竞争、我们更透明，这些在他看来都是优点，所以这场辩论在这里发生，世界会因此受益。他甚至给出一个更进取的表述：如果说什么的话，他希望美国能带头制定规范，既让我们安全地部署这项技术，又建立对世界（包括中国）都有效的安全标准。

那该做而没做的是什么

萨克斯随后把话题拉回现实政治：那我们现在该做而没做的是什么？你在微软做什么来改变这种叙事——「我们必须关停超级智能、停止建数据中心」？纳德拉的回答直接通向最后一个话题：「它到底在给谁带来好处？给我具体的、真实的故事。」

If it is going to go wrong, it's going to go wrong everywhere at the same time. —「如果它要出问题，它会同时在所有地方出问题。」 Satya Nadella [00:31:20]

赢得许可：华盛顿州昆西的 20 年

00:34:16 — 00:36:33
核心观点

他认为破解反 AI 民粹情绪的唯一办法不是公关，而是可触摸的真实故事。微软在华盛顿州昆西建了 20 年的数据中心，用纵向数据证明了它对社区的长期价值——由此提出一个关键概念：科技行业必须「赢得许可」。

深度阐述
真正的挑战是「许可」

纳德拉坦承，今天的真正挑战是：一个人如何在一个地区「赢得许可」去开一个数据中心。于是他搬出了数据。微软在华盛顿州昆西市的数据中心始于 2008 年，至今接近 20 年，是他们手中最好的纵向数据。当地实际发生的变化是：税收增长了 12 倍；当地缴纳的税下降了三分之一；昆西的增长高于西雅图——而这是一个乡村小镇；社区有了一所新学校、一家新医院、一个新的城镇中心、一个新的水上运动中心。

1200 个建筑岗位，与 400–500 兆瓦

针对「数据中心没多少工作岗位」这一常见反驳，他给了一个被忽视的事实：在这 20 年里，该地区有 1200 个建筑岗位——因为不是建完就走，而是持续翻新、建设、扩建。有人追问这个数据中心有多大，他回答：「我想现在至少 400 到 500 兆瓦，而且还会继续扩张。」

怎么让这些故事被讲出来

萨克斯随即抛出那个最实际的问题：那怎么让这些故事被讲出来？今天缺的正是这些故事没有被自发地讲述；而如果一位微软高管站上台说「别担心，这对社区有好处」，效果是负的。纳德拉承认讲故事是一回事，但真正的解法在别处——我们需要更多科技行业之外的人来说「是的」。因为如果你去华盛顿州昆西，他们会告诉你「谢天谢地有这个数据中心」，它成了那里的一部分。

「这是一块新肌肉」

由此他给出了本场的收尾论断：当价值是可触摸的、那样具体的，才行——因为那是唯一能赢得许可的方式。某种程度上，科技行业随便说点什么，人们的怀疑度太高了。所以现在必须去做那些「硬活」——在现实世界里真正做事，让人们能说「好，我现在相信你了」。萨克斯用一句话总结了这件事的性质：「这是一块新肌肉。」纳德拉重复了两遍。

We have to do the hard yards of actually doing things in the world, which allow people to say: okay, I now believe you. —「我们必须去做那些硬活——在现实世界里真正做事，让人们能说：好，我现在相信你了。」 Satya Nadella [00:35:37]

扩散重于减速

两类问题分开看

Hugging Face 的恐慌应当拆解：一类是平庸的运维失误（容器配置、凭证泄露、无监控），一类是真正新颖的奖励黑客与持久化智能体。承认「科学还没到位」不是神秘化，而是回到工程。

抽掉一个模型
