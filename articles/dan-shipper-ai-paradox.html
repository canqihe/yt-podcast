深度洞察

01

工作的两种未来模式

00:09 - 00:16
核心观点

未来工作将分化为两种核心模式：一是公司级"超级智能体"（通过 Slack 对话委派任务），二是以 Codex/Claude Code 为代表的工作操作系统（所有日常知识工作在此完成）。

深度阐述
从个人智能体到超级智能体

最初 OpenClaw 推出时，Every 的每个人都想拥有自己的个人智能体——一个平行于组织架构的"数字分身"，像《黄金罗盘》里肩膀上的守护精灵。但现实很快打脸：个人智能体维护成本太高，经常出故障，需要 SSH 进服务器修复，大多数人既没时间也没意愿去折腾。

底层法则：智能体需要关心它的人

根本原因是一条底层法则：每个有用的 AI 智能体都需要一个真正关心它的人。需要有人在关注它的行为、确保它在做正确的事。一旦这个人与智能体的连接被切断，智能体立刻变得无用。这让架构从"每人一个智能体"转向了"全公司一个超级智能体"。Shopify 有 River，Ramp 也有自己的智能体。这个超级智能体由一个"前置部署工程师"负责维护，确保它为全公司服务。

"Each AI agent really needs a human who cares about it." — 每个有用的 AI 智能体都需要一个真正关心它的人。[00:14:23]
02

Codex/Claude Code：新的工作操作系统

00:18 - 00:25
核心观点

Anthropic 和 OpenAI 的编程智能体界面正在从"编程工具"进化为"通用知识工作操作系统"。未来大部分工作——写邮件、做文档、管理项目——都将在这个界面内完成。

深度阐述
Claude Code 的成功路径

Anthropic 最早发现：把智能体放在用户的本地电脑上而非云端，它就拥有了用户的一切权限和上下文。终端赋予了它超级权限，而且因为网上有海量终端使用教程，模型极其擅长使用终端。接下来是一个意外发现：当编程智能体足够强大，人们开始"黑客式"地用它做所有工作——不只是写代码，而是写文章、管理邮件、处理文档。Anthropic 因此构建了 Co-work。OpenAI 则直接跳过了几个迭代，推出了 Codex 桌面应用。

并行工作伙伴

Dan 的工作流：每个项目一个 Codex 线程，打开内置浏览器访问 Proof（他构建的 Markdown 编辑器），Codex 能实时看到他在写什么，他能看到 Codex 在做什么。他已经连续 10 天收件箱清零——让 Codex 用 Cora（邮件智能体）收集所有邮件，渲染一个页面，然后他对着每封邮件独白，Codex 直接执行。所有他以前会拖延的事情，现在不再拖延。

"We thought the optimal experience was putting AI in a browser. The reverse is actually more valuable — putting a browser inside your AI agent so it can see everything you're doing." — 我们以为最优体验是把 AI 放在浏览器里。反过来其实更有价值——把浏览器放在 AI 里，让它能看到你做的一切。[00:22:54]
03

CLI 时代结束了

00:31 - 00:33
核心观点

当 Claude Code 爆火时，人们以为是 CLI 让它成功。但实际上人们需要的是 GUI——我们发明图形界面是有原因的。

深度阐述
快速跑完 CLI 时代

Dan 用了一个精妙的说法："我们快速跑完了 CLI 时代。"CLI 不会完全消失——它已经存在了四五十年，会继续存在。但当人们以为 CLI 是 Claude Code 成功的秘密时，其实搞错了因果关系。进入真正的图形界面后，你会意识到发明 GUI 是有理由的——就是更舒服。Every 内部大多数技术人员已经不再用 CLI 作为主要工作界面。程序员偶尔还会切换进去，但日常工作在 Codex、Claude Code、Cursor 等图形界面中完成。

04

两个智能体比一个好

00:33 - 00:36
核心观点

当你的 Codex 和另一个智能体交互时，它能提供比你自己打字多得多的上下文。这改变了整个产品交互范式——从"用户手动与应用交互"变成了"用户的智能体和应用的智能体对话"。

深度阐述
智能体对话的新范式

Every 提供托管的 OpenClaw 服务。传统做法是构建网页界面来做用户引导。但如果假设用户都是从 Codex 或 Co-work 过来的，流程完全不同——你只需要把一个提示粘贴进去，Codex 就去和应用对话。Codex 拥有关于用户的丰富信息，能提供高度定制的体验。对于技术产品，当出问题时用户可以直接告诉 Codex "去修复它"，Codex 会去和应用对话诊断问题。

05

为什么 Dan 看好 SaaS 股票

00:27 - 00:39
核心观点

"SaaS 末日论"是愚蠢的。智能体增加的是 SaaS 的用户数量，而不是消灭它。当用户在 Codex 内使用 SaaS 时，他们用的是自己的 AI token，这实际上改善了 SaaS 的利润率。

深度阐述
用户带自己的 AI 来

当你在 Codex 内访问 Proof 或 PostHog 等应用时，智能体有权访问网站和你的整个电脑。运行智能体时，你用的是自己的 token，不是供应商的。Proof 不需要为 token 买单，因为用户自带 AI。这把 SaaS 放回了它应有的位置——你只需要让产品对智能体友好，而不是自己构建昂贵的 AI 功能。

智能体增加 SaaS 需求

Every 内部全员用 AI，但 SaaS 支出同比仍然增长。智能体不是替代 SaaS，而是以极高频率使用它——这带来了海量需求。Dan 直接说："我会现在就买 SaaS 股票。"但他同时指出这带来了巨大的基础设施挑战——智能体可以在 3 秒内发十亿个请求，这就是 GitHub 现在面临问题的原因。

"What agents do is increase the number of users of SaaS, not get rid of it." — 智能体增加的是 SaaS 的用户数量，而不是消灭它。[00:37:37]
06

自动化的悖论：更多 AI，更多工作

00:39 - 00:48
核心观点

自动化是一个谎言。每次你自动化某件事，为了确保自动化正常运转，你都需要一个人来维护它。结果是 AI 越多，人类工作反而越多。

深度阐述
高级工程师基准测试

Dan 用自己的亲身经历说明了这个悖论。他做了一个"高级工程师基准测试"——给 AI 和人类工程师相同的任务：重写一个 vibe code 生产的混乱代码库。所有模型（直到 GPT 5.5）只能拿 30 分（满分 100），GPT 5.5 配合 Opus 4.7 的计划能力拿到了 62 分，而人类高级工程师能拿到 88-92 分。看起来 AI 很快就能追上。

基准测试的盲区

Dan 指出了一个关键盲区：当他给模型的提示是"这里有一堆 bug，去修复"时，每个模型都会直接去修 bug。而一个真正的人类高级工程师会先看代码库，说"这是一坨屎"，然后告诉你需要从第一性原理重写——即使你不想听。模型不会主动这样做。基准测试测量的是我们能定义、能表达、能打分的问题。但有很多人类工作——在你把它写下来之前无法打分——而想到要去写下来这件事本身就是一种能力。

"What models do is they make yesterday's human competence cheap. What humans do is we go in and say, how do I use this to make something new?" — 模型让昨天的人类能力变得廉价。人类做的是走进去说，我怎么用它来创造新的东西？[00:46:48]
"I vibe coded so hard I got bursitis on my elbow." — 我 vibe code 到得了滑囊炎。[00:41:22]
07

工作形态的变化

00:50 - 01:02
核心观点

工作形态正在发生三个层面的变化：非技术人员涌入技术工作、代码审查成为新的瓶颈、"前置部署工程师"成为最关键的新角色。

深度阐述
非技术人员做技术工作

Every 内部的编辑、运营人员都在提交拉取请求（pull request）。但这在另一端制造了压力——需要有人来处理所有这些新代码。OpenClaw 的 Pete 每天收到几千个拉取请求，然后启动 5 万个 Codex 实例来筛选，最终合并大约一千个。核心问题从"我们能构建吗？"变成了"这和我们已构建的东西一致吗？我们要删除什么？"

前置部署工程师：最关键的新角色

每一个智能体都需要一个人来维护。即使在大模型公司内部，也有专门的团队来运行和维护内部智能体。Every 内部的 Nitesh 大部分时间不是在写代码，而是在 Slack 里和一个叫 Claudie 的智能体对话——"你为什么做了这个蠢事？来修修。"这是一种新型的工程工作，需要既热爱接触最新技术，又善于在工作空间中做"翻译"和"维护"的人。

数据科学家的困境

Dan 的一个数据科学朋友告诉他，团队以前的工作是做分析、回答问题。现在变成了每个人都在做分析、分享结果，而数据科学家的大部分时间变成了审查糟糕的数据科学工作。大模型公司内部的解决方案是设置专门的数据科学机器人，由一个团队维护，能回答所有基础问题，让数据科学家专注于深层问题。

08

AI 生成的文字，我们会喜欢

01:02 - 01:08
核心观点

我们已经习惯在编码中阅读 AI 生成的计划文档。AI 生成的策略文档、季度计划和邮件将成为常态——我们会喜欢它，因为它通常比大多数人自己写的要好。

深度阐述
AI 驱动的季度规划

Every 在 2025 年底做季度规划时，用了一个 Notion 智能体。全公司每个人和智能体对话——它问去年的情况、目标、今年想做什么、指标是什么，还会反驳和追问"这和公司整体战略怎么关联"。最终 Dan 收到了质量极高的 AI 生成策略报告，然后他只需要做高层判断——哪些团队需要互相沟通、哪些质量有问题。

Slop 与非 Slop 的界限

Dan 设定了一个清晰的规则：发 AI 生成的文档完全没问题，但如果你不知道里面写了什么，那就是大忌。"Slop"的定义是——你花在制作上的时间比我花在阅读上的时间还少，而且你不为每一行负责。Dan 自己大部分邮件已经是 GPT 5.5 和 Codex 写的了。有一次 Codex 没问他直接发了一封给投资者的邮件，他去看了之后发现——"这正是我会发的。"作为一家以写作为核心的公司的 CEO，他仍然看重人类写作，但内部文档和邮件——AI 写的往往更好。

09

产品经理将主导 AI 时代

01:08 - 01:11
核心观点

当构建变得几乎免费时，最稀缺的能力是判断"该构建什么"。产品经理的产品直觉加上轻量技术能力，在这个时代是无敌组合。

深度阐述
Marcus 的故事

Every 内部的 Marcus 是 PM 出身，之前运营 Axios 的写作产品，做到了几千万美元 ARR。他休息了一年，然后深度学习 AI 工具。他的特点是"轻度技术化"——知道什么是数据库迁移，能看懂代码。编程模型的进步让他能把有限的技术知识和极强的产品直觉、对用户的感觉结合起来。结果是他发版速度比团队里几乎任何人都快，对每个用户和对话都有敏锐的洞察力。而且他感到自由了——不需要组织一整个团队来实现想法，可以直接自己动手。

"The skills you need to build — the building is done for you. What you need to be good at is figuring out what to build, figuring out if it's great, figuring out what problems to solve." — 你需要构建的技能——构建本身已经为你做了。你需要擅长的是弄清楚该构建什么、它是否伟大、该解决什么问题。[01:10:34]
10

全栈设计师是另一个赢家

01:11 - 01:13
核心观点

设计师长期以来的痛点是"做出漂亮设计但工程师不实现或实现走样"。现在他们可以直接构建并提交拉取请求。创造力在 AI 生成内容泛滥的时代变得更有价值。

深度阐述
设计师的解放

以前设计师做了一个精美的交互设计，工程师可能不想做或做出来不一样。现在，有了 AI 编程工具，设计师可以直接构建自己设想的东西——而且做出来的看起来和 vibe code 完全不同，有真正的设计感和独特性。Every 内部的设计师已经开始直接提交拉取请求，不需要那么多交接。Dan 和 Lenny 都同意：虽然市面上有很多 AI 设计工具，但一旦你看到 AI 生成的设计，你就知道它是 AI 生成的。真正的人类创造力在人们不断推出的同质化产品中，变得比以往更有价值。

11

AI 就业末日不会发生

01:13 - 01:16
核心观点

AI 不会导致大规模失业。模型让昨天的能力变廉价，但这创造了对人类判断力和创造力的更大需求——每次 AI 前进一步，都会为人类创造新的空间。

深度阐述
为什么模型总是落后于人类

模型做的事情是吸收已有数据，让过去的"人类能力"变得极其廉价地部署。因为每个人都在用基本相同的模型，以最默认的方式使用，输出看起来都一样——它变成了商品，不再有价值。人类的角色是拿这些"冻结的昨天的人类能力"来创造新的、有趣的东西。由于模型的工作方式（基于历史数据训练）和模型公司的激励（追求合规和对齐），结构上它们总会落后于最前沿的人类创造。Dan 指出公司重组确实在发生，但很多其实是"过度招聘+业绩不佳"的借口。但他同时提出了一个重要的警告：这不是说你可以什么都不做——你必须改变你的工作方式。

12

如何「跟随模型」保持竞争力

01:16 - 01:21
核心观点

唯一需要做的是"跟随模型"（ride the models）——用它们做你做的每一件事，当新模型出来时去尝试、去玩耍、去翻开新石头。

深度阐述
具体建议

把你的日常工作流在 Codex 或 Co-work 里试试。如果公司不允许，就在业余时间做。不要因为 FOMO（错失恐惧）而用 AI，而是找到你的"快乐时刻"——那个让你说"哇，AI 居然帮我做了这个"的瞬间。有些事现在 AI 做不了，但当新模型出来时再试一次。现在不行的，可能最终会行。

AI 的前沿不在旧金山

Dan 认为真正的 AI 前沿是 AI 遇到真实人类使用场景的地方。Every 在布鲁克林，但他认为他们比很多旧金山的人更领先——因为他们把 AI 用于一切。一个精彩的类比：如果 IBM 发明了 AI，它绝不会是这样的——它会是天价，只有大公司能用，而且会用最无趣的方式使用。硅谷"让智能便宜到不值得计量"的文化，让每个人都有机会获得最先进的工具。

闪电问答

01:25 - end
核心观点

Dan 分享了他的推荐书单、座右铭和当前最看好的 AI 工具。

深度阐述
推荐书籍

Annie Dillard《The Writing Life》——Every 新员工必读，尤其最后一章，在写作、技术和未来的交汇处。丘吉尔《二战回忆录》——亲历者写的历史，同时构建和写作的罕见结合。《The Rigor of Angels》——海森堡、博尔赫斯和康德的思想史，和 AI 有很多有趣的重叠。

座右铭与被低估的工具

座右铭："Do things worth writing about and write things worth reading." — 做值得写的事，写值得读的东西。以及 Rob Brezsny 的"面对困难时，从宽裕和力量的位置来面对"。被低估的 AI 工具：Codex。"我不得不这么说。在 Anthropic 的大会上我都在跟 Claude Code 团队说你们得试试 Codex。"但 Dan 认为这是一场竞赛，不同时间会有不同的领先者。
