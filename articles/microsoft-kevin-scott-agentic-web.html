为智能体打造的 互联网

2025 年，微软 CTO Kevin Scott 押下一个大赌注：agentic web（智能体网络）将成为 AI 的下一件大事。这个判断的底层逻辑非常朴素——智能体要真正有用，就必须能「代表你办事」，而这意味着它们需要访问构成互联网的那些庞杂工具、数据与系统。今天，这个赌注正在兑现：MCP 协议被接入 Windows、NLWeb 开源、AI 写代码从演示变成日常。但很少有人问过：当一个 AI 被赋予「行动权」，我们到底需要一个怎样的互联网来承载它？

核心要点

01

能力过剩

模型推理能力已领先于产品实际交付。行业下一阶段竞争的核心，是把「模型能做」变成「用户真正用到」。

02

访问即权力

智能体的价值上限由「访问权」决定——能触及的工具、数据、系统越广，它能替你办的事越多。开放的 agentic web 是起飞的前提。

03

协议定胜负

MCP 之于智能体网络，如同 HTTP 之于互联网。极简、开放、可叠加的协议，是生态走向普及的支点，其安全模型值得先行者提前卡位。

04

安全可以双赢

「封闭换安全、开放换创新」是虚假的二元对立——AI 本身就能充当个人安全代理，主动察觉并交叉验证可疑行为。

05

手艺不靠守旧

工具会变，争论永远在。真正的高手既保留对工艺的执念，又对新工具保持好奇——微软 CTO 用 VI，也后悔没早学 3D 打印机。

06

异步是终局

人与智能体将从「你问它答」的同步模式，走向「派活、等待、交接」的异步模式——智能体开始真正独立干活，这是下一个里程碑。

为什么今年不再谈规模定律：能力过剩（capability overhang）

00:02:49 - 00:04:31
核心观点

模型的实际能力，已经跑到了产品实际交付能力的前面。中间那道「能力过剩」的落差，才是整个行业今年真正要补的功课。

深度阐述
规模定律不再有争议

Dan Shipper 开场回顾了 2024 年 Kevin 提出的两大主题——「智能体将无处不在」（已经应验）和「规模定律」（每两年性能大幅提升的曲线）。但 2025 年，Kevin 刻意把聚光灯从规模定律上移开了。原因之一是：年复一年的进展让「模型会不会停止进步」的怀疑几乎销声匿迹，这个话题不再需要反复证明。

能力过剩（capability overhang）

更重要的是，他提出一个概念叫 capability overhang（能力过剩）——模型在推理上的能力，已经略微跑到了我们把它用在产品里时实际发挥出来的能力前面。整个行业需要集体努力，去弥合「模型能做什么」与「用户实际用到了什么」之间的落差。

暴露的短板：智能体记忆

过去一年智能体的爆发式涌现，暴露了推理之外的短板。Kevin 在 Build 主题演讲中点名了 agentic memory（智能体记忆）：现在的智能体本质上是「事务式」的——你在一个任务内记忆连贯，任务结束记忆就可能归零，下次一切从头开始。这直接抑制了人类把「越来越复杂的任务」放心委托给它的能力。

我们年复一年地证明，规模定律依然完好、运行良好，已经不需要再提醒大家这件事了。模型的推理能力已经略微跑到了产品实际发挥能力的前面。 00:02:35
02

智能体要「有用」，先要「能访问」

00:04:31 - 00:06:48
核心观点

智能体的价值上限，取决于它对「行动」的访问权——能不能用工具、改系统、查信息。为此需要一套像互联网一样的开放生态，而不是孤岛式的单点集成。

深度阐述
被绑住的手

Kevin 把「智能体为什么还不够好用」归结为一个结构性问题：如果智能体要代表你采取行动，它就必须能使用工具、修改系统中的状态、查阅多样而丰富的信息源。而现在大多数智能体只能做到「你给它一段上下文，它给你一段回复」，它的手被绑住了。

一个「长得像互联网」的生态

要让这件事真正伟大，需要的是一个「长得非常像互联网」的生态：你已经有一个网站，你已经有一个对外服务的 API，那就要把这些东西「接通」（plumb），让智能体能和它们对话，并且让所有参与方的激励对齐——内容提供方、工具提供方、智能体厂商、用户，都能在参与中获得对自己有意义的好处。

访问权即权力

Dan Shipper 把这套逻辑复述成一句话：智能体的强大，取决于它的「访问权」——能访问互联网上的一切、你电脑上的一切。而这需要在技术栈的不同层次配套基础设施：运行时层（记忆、身份等）+ 连接层（MCP 把外部世界接入智能体）。

如果智能体要变得有用，它们就必须代表你采取行动。它们得能使用工具、改动系统、查阅丰富多样的信息来源。 00:04:08

微软的双重身份：既是智能体厂商，更是平台公司

00:06:48 - 00:09:10
核心观点

微软参与智能体生态有两条线：一条是把自家智能体做好（为此内部先统一协议），另一条更重要的线是——作为平台公司，解决整个 agentic web 兴起的公共问题。

深度阐述
理由一：内部先统一协议

微软自己生产智能体，为了让自家产品有用，内部必须先解决这些问题。他以「企业级智能体」举例，讲了一个非常工程化的痛点——康威定律。这条源自编译器领域的经验法则说：一个系统设计的结构，往往镜像了生产它的组织架构（「你编译器的阶段数，取决于你有多少个团队在写它」）。用 Kevin 的话说：「你会把组织架构图发布出去。」 如果微软每个部门各自为战，开发出互不兼容的智能体接口，最后暴露给用户的就是一堆乱麻式的内部组织残影。所以作为 CTO，他强制推动：内部所有系统都讲同一种标准协议，所有智能体都通过它对话。

理由二：开放协议才能规模爆发

把视野从企业内部放大到整个行业：要让智能体像当年网页爆发那样被大规模使用，就必须有「所有人都参与」的开放协议，而不是微软一家说了算。

理由三：微软是平台公司

最本质的——微软是平台公司。它在技术上搭建平台长达 50 年，比「自己写智能体」更重要的事情，是帮助解决 agentic web 兴起过程中涌现出的平台级问题。

你会把组织架构图「发布」出去。在微软内部构建智能体时，你肯定不希望把自己的组织架构图暴露给整个世界。 00:07:43

MCP 与 NLWeb：智能体世界的 HTTP 与 HTML

00:09:10 - 00:12:05
核心观点

MCP（Model Context Protocol）在智能体网络里的角色，相当于 HTTP 在互联网里的角色；NLWeb 则相当于 HTML。极简、开放的协议，是智能体生态走向普及的支点。

深度阐述
MCP：智能体世界的 HTTP

一个极其简单的开放协议，解决的问题是「智能体如何接入外部的工具、数据与系统」。它在 agentic web 中的位置，恰如 HTTP 之于互联网——是那个让「万物互联」成为可能的通用语言。微软已把它深度集成进 Windows。

NLWeb：智能体世界的 HTML

NLWeb（Natural Language Web）是微软开源的实验项目，让「网页 / API」可以被自然语言描述和调用，Kevin 把它比作 HTML——内容如何被表达与呈现的那一层。

简单、可组合、可叠加

这套基础设施的价值在于「简单、可组合、可层层叠加」。Dan Shipper 敏锐地提出质疑：互联网的安全模型里有同源策略（same-origin policy）这样的关键防线——网站提供的代码只能在它自己的数据上执行，但 MCP 目前没有对等物，安全模型仍需大量补课。

安全模型如何补课

Kevin 的回应很务实：正因为 MCP 足够简单自洽，社区要确定它的安全模型反而相对容易。他列出的清单包括：智能体身份（identity，让你能构建「这个智能体代表这个人、有权访问这些资源」的授权体系）、权限预协商（智能体主动查询「做这件事需要哪些系统的哪些权限」，向委托它的用户逐项请求「是 / 否」）、以及系统管理员的审批视角。而这一切必须在开放的方式下完成——「我们不需要把它做成专有方案」。

MCP 正在这个智能体网络中扮演着 HTTP 在互联网中的角色，NLWeb 则扮演着 HTML 的角色。你会看到这些简单、可组合、可叠加的东西不断涌现。 00:05:28

开放与安全并非二选一：一个虚假的二元对立

00:12:05 - 00:15:39
核心观点

「纵向一体化能保安全、开放模式只能换创新」是个虚假的二元对立。借助 AI 能力本身，开放系统同样能获得真正稳健的安全。

深度阐述
经典的产业辩论

Dan Shipper 抛出一个经典的产业辩论：AI 产品的市场形态，到底是走纵向一体化（像苹果 App Store：自己拥有模型、UI、中间所有应用，靠封闭保证安全与体验），还是走开放模式（无中央权威，创新多但难做安全）？

无许可创新的价值

Kevin 先承认无许可（permissionless）创新有不可替代的价值：你能无须向任何人申请许可，就构建、分发一个东西。他直白地批评了过去几年涌现出的「中间层」——那些挡在「有点子的人」和「可能受益的人」之间的守门环节，老实说几乎没贡献什么价值。

用 AI 反哺安全

这是全文最具洞察力的部分：他设想一个守护你个人安全需求的智能体——它知道「这些我愿意分享、这些我不愿意分享」，并具备风险评估与交叉验证能力。他讲了一个真实细节：某天早晨他上台前，作为太太账户的备份安全联系人，收到一连串可疑的两步验证配置邮件。他的第一反应不是发邮件（万一邮箱已被非授权访问），而是发短信确认——结果真是太太本人在操作。把这个情境放大：一个掌握你全部通讯渠道的智能体，能主动察觉「有点不对劲」，再调动多个资源去三角验证这次操作合法与否。这正是「开放系统的安全，可以由 AI 本身来兜底」的雏形。

结论：两者兼得

结论是：你可以两者兼得——开放带来的创新，并不必须以牺牲安全为代价。

这可能是一个虚假的二元对立。借助现在已有的 AI 能力，你可以在开放系统里获得真正稳健的安全。你不必二选一。 00:12:42

手艺人的选择：木工、陶艺与不肯换掉的 VI

00:15:39 - 00:20:52
核心观点

AI 写代码不会剥夺「手艺感」——因为四十年间这种争论反复上演，真正重要的是保持对工具的开放心态，而不是守住某种「正统做法」。

深度阐述
41 年程序员

Dan Shipper 提出一个温柔的质疑：有人担心用 AI 写代码会失去「亲手创作」的感觉。Kevin 的回应不是讲技术，而是讲人。他先亮出身份：12 岁写下第一段程序，已经编程 41 年；做木工的时间几乎和编程一样长，还做陶艺、自己做包。

手艺人的方法论信仰

他的观察是：手艺人有强烈的方法论信仰——对工具、材料、组装方式都有执念，而这恰恰是把手艺做到极致的必要条件。但过去四十年里，软件开发本质发生重大改变的节点不止一次，每一次都伴随着同样的争论与恐慌。

「你只有像我小时候那样干这行，才算是真的」

他以木工界的演化举例：他少年时争论的是「用电动工具还算真木匠吗」，今天的争论升级成「用 CNC 数控工具还算真木匠吗」——争议永远存在，但背后的结构一样。对此 Kevin 的态度是：不要劝任何人放弃对工艺的执念，但更要紧的是当工具变化时保持开放。他拿自己开刀——微软 CTO 至今用 VI 写代码，「我拒绝换，哪怕我清楚这在某部分工作上并非最优，但我能选。」

最真诚的遗憾：3D 打印机

他承认自己曾拖延了很久才去学 3D 打印机，结果后悔不已——「它对我做的几乎所有事都太有用了，我本该更早开始。」结论只有一句话：保持好奇，去尝试。对你有用，就用；没用，就放。

这是过去四十年里软件开发本质再一次非平凡的改变，而人们又一次对变革抱着强烈的意见。……保持好奇，去尝试。如果对你有用，就用它；如果没用，就不用。 00:17:00

智能体的百花齐放：胜在理解问题，而非比拼基础设施

00:20:52 - 00:25:33
核心观点

未来不会有一个「一统天下的智能体」，而是大量口味各异的智能体并存——它们的差异化来自对用户问题的独到理解，而不是基础设施的技术壁垒。

深度阐述
一定会有非常多不同的智能体

面对「会不会出现一个万能智能体」的问题，Kevin 给出一个反直觉的判断：一定会有非常多不同的智能体。理由很朴素——当开发者的乐趣之一，就是拥有选择工具的自由，可以试很多、做不理智的尝试；他四十年编程生涯里最恒常的现象，就是人们总是会更换工具。微软的 Copilot 会努力用「好用」去赢得用户，但期望全世界每个开发者都只用同一个工具，既不现实、也不健康。

分化靠「做产品」那一层

智能体之间到底靠什么分化？Kevin 的观点非常清醒：最重要的是「做产品」那一层。他最欣赏的新锐创业公司，不是靠做差异化基础设施来创新，而是因为「认为自己比别人更懂某个人的某个问题」，然后拿来、改造或调优现成基础设施，以世界级水准去解决它。

对一年的预测

他把这个判断延伸成对一年的预测：会过时的争论——还在用「技术没准备好」当借口的人（嫌贵、嫌能力差一点）会严重掉队，因为能力与成本每年都在改善；会升温的主题——人们用智能体去攻克的「问题野心等级」将大幅跃升。他顺带提醒：「押注失败与押注乐观的成本差距，是巨大的。」

最有趣的初创公司不是在用差异化基础设施做创新，而是因为他们认为自己比别人更懂某个问题。……任何把「技术还不成熟」当借口迟迟不开始的人，都会严重掉队。 00:22:30

从同步到异步：智能体工作流的未来

00:25:33 - 00:28:03
核心观点

随着 agentic web 越来越完整、模型规划能力越来越强，人与智能体的交互将从「你问它答」的同步模式，走向「派活等结果」的异步模式。

深度阐述
今天的同步模式

这是 Kevin 对一年后场景的具体推演，也是全片最直观的未来画面。今天的用法是「同步」的：你坐下来，有个想做的事，发出提示词，然后盯着屏幕等它回来，再对响应做点什么。

转向异步委托

Kevin 认为，当智能体网络被接通、模型的推理与规划能力进一步增强，交互会转向「异步」——你丢给它一句「去把这件事搞定」，它就长时间离线运作：打大量调用访问外部系统、等那些真正「采取行动」的事情慢慢回音、整合所有响应、反复迭代，最后在相当长一段时间之后，回来告诉你：「我做到这儿了，接下来轮到你了，该你去采取行动了。」

分工结构的转变

这背后隐含的转变是分工结构的变化：AI 从「秒回的对话者」变成「长时程的代理人」。同步交互意味着人永远是瓶颈，异步委托才让智能体真正承担起独立工作流。Dan Shipper 听完只回了一句话：「听起来是一个我想身处其中的未来。」

你丢给它一句「嘿，去把这件事搞定」，它花很长时间去访问系统、整合响应、反复迭代，最后回来说：「我做到这了，接下来轮到你了。」 00:25:45
