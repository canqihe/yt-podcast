核心要点

01

九月磨一剑

Computer Use 原型在 Labs 里迭代 9 个月，经历 3.5、3.5V2、3.6、3.7 四代模型，最终在 Sonnet 3.7 上突破"能用"的临界点。

02

能力陷阱

Mike 主动从管理数百人的 CPO 降级为独立贡献者，因为"能力区"——你擅长但不让你燃烧的领域——才是最危险的职业位置。

03

两周生死评审

Labs V2 采用激进的两周冲刺机制，每两周所有项目必须向领导层证明"学到了什么"，学够了就结束——AI 时代的机会成本被极度放大。

04

健康科技拐点

Mike 明确将个性化医疗健康视为 AI 最接近爆发的蓝海——模型在三五个月内就从"花哨"进化到"真正有用"的基因数据解析。

05

MCP 新应用商店

MCP 正在催生新型应用分发机制——不是下载 App，而是在智能体框架内直接获得功能。第一个走红的 MCP 应用可能定义一个新品类。

06

困难永存

AI 加速了编码，但没有改变产品最困难的部分——提出正确的问题、面对用户的真实反馈、做出有锋芒的决策。

深度洞察

01

从 Computer Use 到 Claude Code：九个月的漫长探索

00:02:38 - 00:05:12
核心观点

Claude Code 的诞生并非一蹴而就——它源于一个花了 9 个月不断迭代、多次失败才最终找到正确模型配合的原型。

深度阐述
入职第三周就被推上战场

Mike 回忆他加入 Anthropic 第三周就被推上去发布 Sonnet 3.5 的经历。Sonnet 3.5 是第一个真正解锁编程用例的模型，但还不到完整智能体编程的程度。团队围绕它构建了 Computer Use 产品，但问题很多：操作太慢、识别屏幕不够准确，会想点击一个按钮却点到了别处。

9 个月的耐心迭代

那个"不太能用的框架"成为后续突破的关键评估工具。团队每几个月就用新模型在同一个框架上测试，经历了 3.5V2（Mike 称之为"Anthropic 任期内最黑暗的命名决定"）、3.6（仍差一点），直到 Sonnet 3.7 出现。Mike 清楚记得那天——他在纽约出差，收到消息说那个在 Labs 里已经存在 9 个月的原型终于在 3.7 上展现出了真正的生命力。

"One of the dark days of my Anthropic tenure is naming it 3.5V2." — "我在 Anthropic 任期内最黑暗的日子之一就是把它命名为 3.5V2。"
02

从 CPO 到 IC：为什么 Mike 主动选择降级

00:05:10 - 00:10:07
核心观点

Mike 在公司高速增长期主动放弃了管理数百人团队的 CPO 职位，回到一线成为独立贡献者，因为他发现"能力区"才是最危险的地方。

深度阐述
从 30 人到数百人的膨胀

Mike 描述了 Anthropic 产品团队从他加入时约 30 人，到去年年底膨胀到数百人的过程。随着规模增长，工作内容变成了部署、客户沟通、管理层事务。他引用教练的概念——"能力区"：你擅长、做得还行，但这不是让你燃烧的东西。

和 Daniela 的关键对话

Q4 时他开始和 CEO Daniela 对话。他本来考虑离开去做新公司，但 Daniela 问了一个关键问题：是离开 Anthropic，还是想转换角色？Mike 说他爱这家公司，而 Labs V1 因为太成功（所有项目都毕业了）刚好处于暂停状态。于是 Labs V2 启动，Mike 回到他最擅长的角色——builder。每个看到他的人都注意到变化："Mike，你现在看起来好开心。"

"The most dangerous place to be is your zone of competence. You could keep doing it for a very, very long time, but it is not your place of maximum fire." — "能力区是最危险的地方。你可以持续做很长时间，但这不是你最大火力的所在。"
03

Labs V2 的运作：两周生死评审

00:10:06 - 00:15:43
核心观点

Anthropic Labs V2 采用了激进的"两周冲刺"评审机制，每两周所有项目必须向领导层证明学到了什么，学够了就结束——机会成本在 AI 时代被极度放大。

深度阐述
不是激励问题，是防赖问题

Mike 研究了大量公司实验室项目（包括 Alphabet X），发现它们通常试图通过股权激励等方式模拟创业紧迫感。但 Anthropic 的方法不同：不是激励问题，而是防止平庸想法赖着不走。方法就是缩短时间周期——从 V1 的四到六周评审缩短到 V2 的两周冲刺。

小团队 + 前创始人

项目带头人几乎全部是前创始人，团队成员则是创业公司早期员工或"什么都能做"的通用型 builder。从两三个人开始，不要一开始就加五个人，更像创业公司。四个月内，Labs 已经经历了从构思到发布到结束的完整周期多个循环。

04

Labs 正在探索的方向

00:15:42 - 00:18:26
核心观点

Labs 的项目即使被搁置，其学习成果也会转化为实际产品功能——Managed Agent（托管智能体）和 Claude Code 的自我验证能力都源自一个已搁置的长周期项目。

深度阐述
搁置项目也能产出成果

Mike 透露了他之前领导的一个让 Claude 长时间运行的项目已被搁置，但其成果转化为两大功能：Outcomes（结果导向）——Claude 基于评分标准自主完成任务；以及自我验证——Claude Code 通过截图和测试来验证自己的工作。团队甚至让 Claude 录制自己工作的视频，然后回看视频发现问题，比如"那个动画是坏的"——仅靠截图验证看不出来。

个性化生产力软件的愿景

另一个方向是"智能体 + Canvas 画布"的模式扩展到更多应用类型——像 Claude Design 但面向更多形式。Mike 分享了他用 Claude Design 写技术规格的个人体验，以及对高度个性化生产力软件的愿景。

05

AI 蓝海：健康科技是最确定的下一个方向

00:18:25 - 00:25:08
核心观点

Mike 明确将个性化医疗健康视为 AI 最接近爆发拐点的蓝海领域，从基因组分析到补剂优化，模型在三五个月内就从"花哨"变成了"真正有用"。

深度阐述
基因数据解析的质变

有人在 X 上分享了自己在家做全基因组测序的帖子，现在还把这做成了专业上门服务。关键洞察是：Opus 4 级别的模型在解析基因数据和处理化验报告方面，已经从"和医生看差不多"进化到"真正能发现新洞察"。Mike 说："我感觉我们正处于这个拐点上。"

补剂优化与个性化医疗

他在用一个叫 Subco 的服务——输入所有补剂，它分析相互作用后建议砍到四种。下一步可以结合基因数据判断你是否是某种补剂的"超级响应者"。一月份 Anthropic 推出 Claude for Healthcare 时，已经和 Function Health 合作——可以把化验结果导入 Claude 来分析。

消费 AI 的突破性用例仍在寻找

Mike 坦承他一年前在消费 AI 大会上问过这个问题，至今仍没看到答案。但他对 MCP 作为新型分发机制表达了浓厚兴趣——"第一个走红的 MCP 应用会是什么？"这可能是消费级 AI 产品的突破路径。

06

CoWork 的诞生与产品整合的紧迫性

00:25:08 - 00:37:54
核心观点

CoWork 源自 Dario 的一个直觉——"为非编程者做一个 Claude Code"，但 Anthropic 当前的产品碎片化（Chat、CoWork、Claude Code 三分离）是一个亟需修复的"糟糕抽象"。

深度阐述
Dario 的直觉与关键组合

CoWork 的起源是 Dario 观察到一个趋势：人们在用 Claude Code 做非编程的个人用例，但终端对大多数人来说门槛太高。他给出了一个简洁的方向——"为所有其他事情做一个 Claude Code"。关键组合是 Felix（Electron 核心维护者，懂桌面软件）和 Boris（Claude Code 深度专家），把他们放在一起几周就发布了 CoWork。

产品碎片化的问题

Mike 坦承当前的产品体验有问题：CoWork 对话无法同步到 Claude 手机应用；用户记不清"那个是在编程里做的，还是在 Chat 里问的，还是在 CoWork 里"。"感觉我们在按组织架构发布产品。"他暗示未来会整合——不需要是超级应用，但构建模块之间必须互通。CoWork 的增长轨迹和 Claude Code 当年相当甚至更快。

07

与 OpenAI Codex 的竞争：Instagram-Snapchat 的重演

00:28:48 - 00:37:54
核心观点

Mike 将 Anthropic 与 OpenAI 的竞争比作 Instagram 与 Snapchat——不同路径、不同理念、但方向一致，会互相借鉴，最终市场会容纳多个玩家。

深度阐述
Instagram-Snapchat 类比

Mike 承认 Codex 很好、新模型很好、Codex 发展得不错。但他用 Instagram 与 Snapchat 的竞争来类比：Instagram 的优势是"每周一张精心修过的照片"，需要变得更自由——于是引入了 Stories；Snap 的优势是阅后即焚的亲密感，后来也想触及名人/网红的影响力。两家最终各自演化，互相影响。

与客户竞争的难题

Claude Design 和 Figma 的争议——Mike 曾在 Figma 董事会上，不得不辞职。他回应说："我很爱 Dylan（Figma CEO），我非常尊重他们在做的事情。"他认为 Claude Design 和 Figma 服务不同用例——前者适合探索和快速原型，后者适合精加工和协作。

"A diversity of products to exist — that would be a tragedy if there's only one." — "产品多样性应该存在——如果只有一个产品那将是一场悲剧。"
08

MCP 作为新型应用商店

00:37:54 - 00:42:38
核心观点

MCP（模型上下文协议）可能正在催生一种新型的应用分发机制——不是下载 App，而是在智能体框架内直接获得功能。

深度阐述
MCP 连接器排行榜的启示

Mike 分享了一个有趣的观察：一个非营利探索工具在 MCP 连接器排行榜上短暂进入前五，和 Gmail、Slack 并列，引起了巨大关注。这暗示了一种新的增长路径。

新的分发机制

当注意力转向聊天智能体时，"在聊天应用里走红"还是一个未被定义的概念。MCP 可能成为新的应用商店——不是下载 App，而是连接功能。如果能在 Claude 或 ChatGPT 的框架内提供足够价值，然后找到有趣的方式传播，第一个走红的 MCP 应用可能就是一个消费级产品。

09

重建 Burbn 的启示：困难的事情仍然困难

00:42:38 - 00:46:39
核心观点

Mike 用 Claude 在几分钟内重建了 Instagram 的前身 Burbn——但核心结论是：AI 加速了编码，却没有改变产品最困难的部分——提出正确的问题、面对用户的真实反馈。

深度阐述
Claude "过度构建"了 Burbn

有趣的细节：Claude 在重建 Burbn 时给它加了滤镜功能，但 Burbn 当年没有滤镜。因为 Burbn 是纯网页的，当时没有 WebGL 技术做图片滤镜。他们到 Instagram 才推出了滤镜。从 Burbn 到 Instagram 的转型过程中，编码速度不是限制因素，限制因素是思考和探索过程。

过早决策的风险

如果大语言模型在一开始就帮你做了太多决定，它可能阻止你找到那个与众不同的形状。"什么 AI 会建议'阅后即焚'是解决社交媒体压力的方案？那是一个疯狂的想法，所有人都说 Evan（Snapchat 创始人）错了——直到它开始奏效。"

"The hard things are still hard." — "困难的事情仍然困难。"
10

AI 越强，人类创造力越重要

00:46:39 - 00:51:23
核心观点

在 AI 编程时代，人的核心角色变成了"清晰表达北极星，然后帮助 Claude 高效收敛"——不是管理者，不是架构师，更像是一个向导（Sherpa）。

深度阐述
正确和错误的 AI 协作方式

错误方式：给 Claude 一个高层功能描述 → 它构建出来、功能验证通过 → 但看着结果说"我会做得不一样"，而东西已经做完了。正确方式：先花时间和 Claude 充分讨论规格，形成共识，然后让它实现。有人内部总结得很好——"我们用 Claude 编程时的整个工作就是清晰表达北极星，然后帮助收敛。"

算力限制的深刻体验

Mike 加入初期以为 GPU 可以像 AWS 一样"开新实例"，被告知"用完了就完了"时才意识到这是一个完全不同的世界。Claude Code 在 Q1 实现了 80 倍增长，这种速度连 Instagram 的早期都比不上。

11

Anthropic 的文化内核

00:51:23 - 00:54:31
核心观点

Anthropic 的内部信念是：公司的目标不是建立大型商业企业，而是推动世界走向 AI 的美好未来。这个核心信念解释了所有下游决策。

深度阐述
透明与使命驱动

Mike 坦率回应了外部常见的质疑——"制造恐慌"、"监管俘获"、"抬高估值"。Dario 比他认识的大多数人都更直接表达想法，不是出于策略计算。公司保持脚踏实地的原因是使命驱动而非商业驱动。

关于模型安全

内部信念是他们应该能够安全地发布 Mythos 级别的模型，而还没做到这件事被视为"不好"——不是骄傲，而是需要解决的问题。他们在内部已经用 Mythos 构建了大量软件，效果很好，但安全发布仍然是最优先的事项。

外部视角
联合主持人 Ellis 补充了一个有趣的外部视角：Anthropic 的文化让他联想到 Apple——好的方面（注重工艺、注重细节、对产品的关注）和不好的方面（有点内闭、有点扭曲现实的力量）。面试中的文化考察部分非常严格，问题包括"你做过的最难的道德权衡是什么"这类深度探查。
12

给焦虑者的回答：人类不可替代的东西

00:54:31 - 00:56:58
核心观点

面对 AI 带来的就业焦虑，Mike 不会说"不用担心"——他相信确实会发生大的变化，但关系、好奇心、创造力和组织能力仍然是人类的核心优势。

深度阐述
四点建议

第一，承认现实——变化已经在发生，可以不同意时间线但不否认方向。第二，需要全社会对话——这不是一家公司或一个政府部门能解决的，需要税收结构改革、再培训等全方位措施。第三，保持人类核心能力——关系、好奇心、创造力、组织人们朝着目标前进的能力仍然很重要。第四，不要把当前状态当作终局——保持好奇、积极探索前沿的人，可能会参与创造全新的职业类别。

"The things that will still remain human and ineffable and important are still relationships and curiosity and creativity and the ability to organize people towards an end." — "仍然属于人类的、难以言喻且重要的东西——关系、好奇心、创造力、组织人们朝着目标前进的能力。"

精华收获

⚡

痛点驱动

Labs V2 最有效的创新机制是"两周生死评审"——不是因为焦虑不好，而是因为 AI 时代的机会成本太高，平庸想法赖着不走比快速失败更危险。

🎯

能力陷阱

"能力区"（你擅长但不让你燃烧的领域）是最危险的职业位置——你可能在那里待很久而不自知。

🔄

延迟收获

Computer Use 花了 9 个月才等到正确的模型；搁置的 Labs 项目转化为了 Managed Agent。在 AI 产品开发中，"失败"的项目可能只是时机未到的成功。

🧭

表达先于执行

用 AI 编程的正确姿势是"先充分讨论形成共识，再让它执行"——人的价值不在于写代码，而在于清晰表达目标。

🚀

MCP 即分发

MCP 正在创造一种新型应用商店模式——不是下载 App，而是在智能体框架内直接获得功能。第一个走红的 MCP 应用可能定义一个新品类。

💡

困难永存

AI 加速了编码，但没有改变产品开发中最困难的部分——提出正确的问题、面对用户的真实反馈、做出有锋芒的决策。什么 AI 会想到"阅后即焚"？
