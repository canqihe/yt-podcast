核心观点

对于 Boris Cherny 和他的团队来说，AI 已经能够 100% 完成编码工作，这标志着传统意义上的"编程"已经不再是瓶颈。

深度阐述
技术选择背后的逻辑

Claude Code 团队选择 TypeScript 和 React 作为技术栈，并非出于个人偏好，而是因为这两种技术在 AI 模型的训练数据中占据主导地位（"on distribution"）。当项目开始时，模型还不够聪明，需要使用它最熟悉的技术栈才能有效工作。虽然今天的模型已经能够学习新的语言和框架，但这个历史选择揭示了 AI 编程助手的一个关键规律：模型的能力边界与其训练数据的覆盖范围直接相关。

临界点的到来

从 2024 年 10 月到 11 月左右，Boris 的团队达到了一个临界点：模型开始能够编写 100% 的代码。从那时起，Boris 的个人工作方式发生了根本性的转变。他现在每天通常发出几十个 PR，有一天甚至达到了 150 个 PR 的记录——这纯粹是为了测试系统的极限。

革命性启示

最革命性的产品不一定需要最复杂的技术实现。Claude Code 本身并不复杂，它只是一个使用标准技术栈构建的相对简单的应用。但 Boris 也承认，"编程已解决"并非普遍真理。对于非常复杂的代码库，或者模型还不擅长的小众语言，人类程序员仍然不可或缺。然而，趋势是明确的：随着每个新模型的发布，能够被完全自动化处理的代码范围在不断扩大。

"对于我来说这对我来说这对我来说是 100%。像嗯，Claude code 代码库，嗯，你知道，它泄露了，所以你知道，人们知道。嗯，它很简单。它只是像 TypeScript 和 React。像没有什么大秘密。"00:05:38

极端的工作方式革命

00:06:50 - 00:08:52
核心观点

Boris 的工作方式已经完全脱离了传统程序员的模式：他主要使用手机，通过多个并行的 AI 智能体循环来完成工作。

深度阐述
来自未来的工作流

Boris 分享的个人工作流程听起来像是来自未来。他现在大部分工作都在手机上完成，通过 Claude 应用中的"代码"标签管理 5-10 个同时进行的会话。这些会话中又包含数百个并行的 AI 智能体，在夜间甚至会扩展到数千个智能体进行深度工作。

Loop 的概念

这个工作方式的核心是一个名为"/loop"的命令，它可能是整个系统中最重要的创新之一。Loop 的概念很简单：它允许 Claude 使用 cron 调度系统创建重复性任务，可以每分钟、每 5 分钟或每天运行。Boris 目前有几十个这样的循环在同时运行：一个循环负责"照看"他的 PR，自动修复 CI（持续集成）问题并执行变基；一个循环保持 CI 健康状态，当出现不稳定的测试时自动修复；一个循环每 30 分钟从 Twitter 抓取反馈并为他聚类分析。

全新计算范式

这种工作方式的意义远超个人效率的提升。它代表了一种全新的计算范式：人类不再直接操作计算机，而是通过描述意图和目标，让 AI 智能体自主调度和执行任务。更令人瞩目的是，Anthropic 最近推出了"例程"（Routines）功能，这是 Loop 的服务器端版本。即使关闭笔记本电脑，这些循环任务仍在后台继续运行。这意味着工作不再受限于设备或时间——AI 智能体在持续不断地为你工作。

组织形式的深远影响

这种工作方式的转变对软件工程的组织形式有深远影响。当一个程序员可以同时管理数百个并行任务，当 AI 智能体可以 24/7 无间断工作时，传统的项目管理、进度跟踪和协作方式都需要重新思考。

未来的团队结构：跨学科通才的崛起

深度阐述
跨学科通才的定义

Boris 对未来团队结构的预测反映了他已经在 Claude Code 团队中实践的模式。今天我们所说的"通才工程师"通常指的是能够处理前端、后端、移动端等多个技术领域的工程师。但 Boris 认为真正的通才是跨越学科边界的。

Claude Code 团队的实践

在 Claude Code 团队中，这种跨学科通才已经成为常态：工程经理编写代码、产品经理编写代码、设计师编写代码、数据科学家编写代码、财务人员编写代码、用户研究人员编写代码。这个现象的背后是一个重要的洞察：当编程不再是一项专业技能，而是一种像读写能力一样的基础技能时，它将成为所有知识工作者的工具。这并不意味着编程失去了价值，而是说它从一种专业能力变成了一种通用能力。

传统流程的颠覆

更重要的是，这种模式可能解决长期困扰产品开发的一个核心问题：信息在传递过程中的损失。当需要通过文档、会议等方式将产品意图传达给工程团队时，细节不可避免地会丢失或误解。当产品负责人能够直接与 AI 一起实现想法时，这种信息损耗将被最小化。

"所以，像我们的工程经理、产品经理、设计师、数据科学家、财务人员、用户研究人员，我们团队上的每个人都写代码。"00:09:45

SaaS 末日还是新生？七种力量的重新洗牌

00:10:26 - 00:12:59
核心观点

AI 将重塑商业竞争的"七种力量"框架，使转换成本和流程权力变得不再重要，而网络效应、规模经济等传统护城河将更加关键。

深度阐述
七种力量框架

Boris 引用了知名播客《Acquired》经常讨论的"七种力量"框架（来自 Hamilton Helmer 的《7 Powers》），并分析 AI 如何重新平衡这些竞争力量。

将要失去重要性的力量

转换成本：传统上，一旦客户采用了某个软件系统，迁移到竞争对手的成本很高。但在 AI 时代，AI 模型可以帮助客户相对容易地将业务逻辑从一个系统迁移到另一个系统，大大降低了转换成本。流程权力：许多公司的竞争优势建立在独特的复杂工作流程和专有流程知识上。但随着 Claude 等模型的进步，AI 能够通过"爬山算法"自动优化任何给定的流程——给定一个目标，它会不断迭代直到达成。这意味着基于独特流程的竞争优势将更难维持。

将保持重要性的力量

网络效应：用户越多，产品价值越高（如社交网络、市场平台）；规模经济：规模越大，单位成本越低；垄断资源：对关键资源的独占 access。这些在 AI 时代仍然保持其重要性。

初创公司机遇

Boris 对 SaaS 行业的最终预测是乐观的：他认为未来 10 年内，颠覆性初创公司的数量将增加 10 倍。这个预测基于一个关键洞察：大公司在采用 AI 方面面临结构性劣势，而初创公司可以从头开始构建"AI 原生"的业务流程。大公司面临的挑战包括：需要改造现有的业务流程、需要重新培训员工、会遇到内部阻力。相比之下，初创公司可以从零开始，用 AI 原生的方式构建一切。

"像转换成本，因为你可以只是使用模型，你可以从一个东西移植到不同的东西。另一个变得不那么重要的是流程权力，因为对于其模式是像工作流程和流程和类似事情的公司，Claude 变得非常擅长弄清楚流程。"00:11:34

印刷机时刻：软件开发的民主化

00:15:01 - 00:17:17
核心观点

软件开发正在经历类似 15 世纪印刷机革命的民主化进程，将从专业技能变成人人可用的基础技能。

深度阐述
印刷机类比

这是整个对话中最具启发性的类比之一。Boris 描绘了 15 世纪欧洲的识字率革命：印刷机前只有约 10% 的欧洲人口识字，识字者通常受雇于不识字的国王和领主，专门负责读写工作；读写是一种专业技能，不是普遍能力。印刷机后，在第一台印刷机后的 50 年内，欧洲发表的文学作品超过了之前 1000 年的总和，书籍成本下降了约 100 倍，经过几个世纪（需要建立教育系统、改变劳动结构），全球识字率提升到约 70%。

更快的速度

Boris 认为软件开发的民主化将遵循类似的轨迹，但速度会快得多。这是一个令人震撼的预测——如果我们确实在几十年内看到软件开发成为像读写一样的基础能力，这将彻底重塑教育、就业和社会结构。

专业程序员不会消失

这个类比有一个重要含义：专业程序员不会消失，就像今天仍然有专业作家一样。但编程将从"专业技能"变成"基础技能"，大多数人都能进行基本的软件开发，就像今天大多数人都能写基本的邮件或文档一样。

领域知识 > 编码技能

Boris 给出了一个具体的例子：会计软件。他认为，甚至今天，编写会计软件的最佳人选可能不是工程师，而是真正优秀的会计师——因为他们最了解领域知识，而编码是"容易的部分"。这个观点揭示了一个深刻的转变：在 AI 时代，领域知识的价值将超过编码技能。当编码不再是瓶颈时，最关键的问题变成"要构建什么"和"为什么要构建"，而不是"如何构建"。

"我认为即将发生的事情，它将比 50 年快得多，是软件将是一件完全民主化的事情，任何人都可以做。"00:17:00

核心观点

深度阐述
模型能力几乎没有差距

这是一个非常重要的洞察。当观众问及 Anthropic 与外界的时间差距时，Boris 的回答出人意料：在模型能力方面几乎没有差距，因为 Anthropic 使用的是和公众相同的模型（主要是 Opus 4.7）。

真正的差距在组织层面

真正的差距在于组织层面。在 Anthropic，每个员工都使用 Claude 处理所有工作。更令人瞩目的是，他们的 AI 智能体之间会自主协作：当 Boris 的 AI 智能体在循环中编码时，它们会通过 Slack 与其他员工的 AI 智能体沟通，共同解决未知问题。

组织的彻底转型

"我们不再有任何地方手动编写的代码。所有的 SQL 都是由模型编写的。"这句话反映了一个组织的彻底转型。这不仅是技术的改变，更是工作文化、协作流程、组织结构的全方位重构。

从被动到主动

工具集成：MCP 与计算机使用

00:21:57 - 00:23:36
核心观点

通过 MCP（Model Context Protocol）和计算机使用功能，AI 可以访问几乎所有软件工具，无论是云端应用还是本地桌面软件。

深度阐述
MCP 统一协议

Claude Code 的一个关键优势是它能够深度集成开发者本地的工具和工作流程。但对于一般知识工作（如使用 Salesforce、Google Docs 等），如何提供类似深度的集成？Boris 的答案很简单：MCP。这是 Anthropic 开发的一种统一协议，允许 AI 模型连接到各种外部工具和服务。无论是 Claude AI、Claude CLI 还是 Claude Code，都可以通过相同的 MCP 连接器访问 Salesforce、Google Docs、Google Calendar 等服务。

计算机使用作为通用接口

对于没有 MCP 连接器的系统，"计算机使用"（Computer Use）功能充当通用接口。Boris 表示 Anthropic 在计算机使用方面"相当领先"，通过这个功能，AI 可以操作几乎任何计算机上的软件。

抽象和统一

虽然目前计算机使用"很慢"，但随着模型（特别是 4.7）的改进，它在质量上已经表现良好。这意味着 AI 不再需要专用的 API 或集成就能使用现有的软件工具——它可以直接像人类一样操作界面。这句话揭示了技术实现的本质：无论通过 MCP、API 还是计算机使用，对模型而言，这些都是与外部世界交互的方式，本质上都是 token 的输入输出。这种抽象和统一是构建通用 AI 能力的关键。
