02

生产力飞跃

04

Boris 已不直接写代码，甚至不直接提示 Claude——他有一个 Claude 负责提示其他 Claude，个人杠杆率呈指数级增长。

深度洞察

01

指数级增长：从未见过的曲线

00:39 - 05:40
核心观点

Claude Code 的用户增长速度超出了 Anthropic 内部所有人的预期，每一次新模型发布都带来了一个新的增长拐点。

深度阐述
内部预判与爆发

Boris Cherny 回忆，在 Claude Code 向 Anthropic 外部发布之前，内部数据就已经预示了这是一款爆款产品。真正的爆发始于 2024 年 5 月 Opus 4 和 Sonnet 4 的发布，增长曲线开始呈指数级上升。此后 Opus 4.5（2024 年 11 月）、Opus 4.6（2025 年 2 月）、Opus 4.7 每一次发布都带来了新的加速拐点。团队中很多成员曾在 Facebook 等大型科技公司经历过所谓的「超高速增长」产品，但即使是这些人也承认从未见过如此陡峭的增长曲线。

产品 vs API 的地位转变

Anthropic CEO Dario Amodei 近期透露，对 Anthropic 产品的需求同比增长了 80 倍。一个值得注意的转变是：一年前 API 占据了使用量和收入的绝大部分，如今 Claude Code 等 Anthropic 自营产品的增速已经使其成为一个不可忽视的力量。Boris 用「混合」一词来描述 API 和产品的关系，暗示两者已经并驾齐驱。

做产品的理由

Cherny 透露了一个历史细节：在 Anthropic 早期，「是否应该做产品」本身就是一个激烈的争论。最终决定做产品的理由有两层——一是争夺开发者心智，二是为了 AI 安全研究：自营产品让 Anthropic 能更直接地观察模型在真实场景中的行为，从而更好地理解和改进安全性。

"I've just never seen growth this steep. And then it just kept going more and more exponential." — "我就是从未见过如此陡峭的增长。然后它就一直越来越呈指数级增长。"
02

从聊天机器人到智能体：一个微小的差异

05:40 - 09:22
核心观点

Claude Code 的核心创新不在于「用自然语言写代码」，而在于从聊天机器人到智能体的范式跃迁——关键差异是「工具使用能力」。

深度阐述
从文本编辑器到智能体

Boris Cherny 对「用纯英语构建网站和软件」这个描述表示认可，但认为真正的突破在于：Claude Code 是一个能使用工具的智能体（agent），而不是一个只能对话的聊天机器人。一年半前，AI 对工程师来说就是一个聊天界面。Anthropic 团队观察到两个关键趋势：模型在编程方面越来越强，在使用工具方面也越来越好。他们做了一个大胆的赌注——放弃当时所有人都在用的「花哨文本编辑器」范式，转向一个完全不同的方向。

使用场景的扩展

这个「微小的差异」是：聊天机器人只能来回对话，而智能体可以使用你的浏览器、操作你的电脑、编辑你的文件。仅仅一年半前，还没有任何 AI 产品能够编辑你桌面上的文件。第一波是开发者用 Claude Code 写代码；第二波是非技术人员通过指挥 AI 智能体来构建工作流软件、网站，甚至通过 Co-work 来完成订机票等日常任务。

"The thing that made Claude Code different from chatbots at the time was Claude Code can use tools. And this is it. Like this is just the difference." — "Claude Code 与当时聊天机器人的区别在于 Claude Code 可以使用工具。就是这样，这就是区别。"
03

让 AI 帮你订机票：从怀疑到信任

09:22 - 12:45
核心观点

Boris 亲自用 Co-work 配合 Opus 4.7 完成了复杂的跨国行程规划——八张机票加五家酒店，标志着 AI 智能体已经能处理多步骤、多约束的现实世界任务。

深度阐述
亲身案例

为了 Code with Claude 活动的全球巡回（伦敦、东京等五站），Boris 把大概的日程告诉了 Co-work，让它查看邮件和日历来核对。Co-work 不仅找出了两个他遗漏的站点，还纠正了他提供的几个错误日期。最终它在后台自行完成了八张机票和五家酒店的预订。只有一家酒店位置不对，他要求重订，几秒就搞定了。

初学者心态

Boris 指出这是他使用过的第一种每个月都有阶梯式能力提升的技术。但更深层的问题在于用户心理：随着模型能力的阶梯式提升，用户必须不断调整自己的预期。一年前的工程师可能认为 AI「一次只能写几行代码」——这在当时是真的。但如果他们今天重新试用，体验会完全不同。用户需要保持「初学者心态」，不断重新尝试那些之前失败的用例，因为下一个模型可能就完美解决了。

"This is the first technology I've used like this where every month there's a step change in what it can do." — "这是我使用过的第一种每个月都有阶梯式进步的技术。"
04

Token 最大化 vs 真实需求

12:45 - 21:27
核心观点

Token 最大化（人为膨胀 AI 使用量来刷 KPI）只是极少数现象，真正的驱动力是数百个百分点的生产力提升。但企业要从 AI 中获益，需要的不是强制指标，而是组织文化的根本变革。

深度阐述
亚马逊案例与真实比例

《金融时报》报道亚马逊员工使用 AI 工具执行不必要的任务来虚增使用分数，一些人运行几小时的自动化任务然后删除，只为了达成 80% 开发者每周使用 AI 的目标。Boris 并不回避这个问题，但他认为 token 最大化只占极小的比例。他以自己前 Facebook 员工的身份提供背景——在 Claude 出现之前，Facebook 有庞大的团队专门做工程师生产力提升，辛辛苦苦一整年可能只获得 1%-3% 的改善。而 Claude 带来的是数百个百分点的增长——Anthropic 自己报告的数据是每位工程师的代码产出量增长 250%，同时代码质量保持稳定。

三条建议

给每个人 token 让人们自由实验；给心理安全感让试错成为可能；不要预判谁是创新者——生产力提升几乎总是来自意想不到的人，可能是角落里的会计、某个市场人员，或者是刚毕业的新人。

90 年代的历史镜鉴

Boris 引用了 90 年代《哈佛商业评论》的一篇经典文章：当时个人电脑正在取代大型机，但很多公司看不到生产力提升。文章的结论是：如果计算机只是放在业务流程的外围，你还保留着纸质档案柜和抽屉里的文件，你不会受益。你必须把计算机放在业务流程的中心。他认为 AI 今天面临同样的挑战——不是技术不行，而是组织还没有围绕它重新设计流程。

"The productivity improvements and the innovations do not come from the people you expect. It could be like an accountant somewhere in the corner of your org that just automates accounting in a way that no engineer would have thought of." — "生产力提升和创新并非来自你预期的人。可能是组织某个角落的会计，以工程师都想不到的方式自动化了整个会计流程。"
05

AI 智能体的效率困境

21:27 - 30:45
核心观点

今天的模型在智能和效率之间存在张力。但优先优化智能再回头优化效率是正确的策略——一年半前 Claude Code 还会陷入循环写不出好代码，如今它已经能编写整个产品。

深度阐述
PDF 导出死循环

Alex 分享了一个亲身经历的「效率陷阱」：用 Co-work 配合 Opus 4.7 制作 PowerPoint 并导出 PDF 时，模型陷入了工具循环——不停地尝试各种方法，消耗大量 token，就是无法完成简单的导出。最终模型自己也承认：「我欠你一个道歉，我钻了牛角尖，担心一个实际上并不存在的限制。」

三个维度与两个旋钮

Boris 提供了一个框架：模型有三个维度——智能、速度和效率，优先级应该是智能第一。为了帮助用户控制平衡，Claude Code 提供了两个调节旋钮：模型选择（Opus 最大、Sonnet 居中、Haiku 最小）和 effort（努力程度）设置——从 low 到 maximum。

历史证据

一年半前的 Claude Code 经常陷入循环、写出糟糕的代码。今天，Claude Code 100% 由自己编写，Co-work 100% 由 Claude Code 编写。在 Y Combinator 的百人房间里约一半人举手表示 100% 的代码由 Claude Code 编写。这个进步速度说明，效率问题会随着智能提升而自然缓解。

"Claude Code is 100% written by Claude Code. Co-work is 100% written by Claude Code." — "Claude Code 100% 是用 Claude Code 写的。Co-work 100% 是用 Claude Code 写的。"
06

速率限制：增长最快的痛

30:45 - 36:03
核心观点

速率限制是用户最大的痛点，但真正的挑战不是配额不够，而是使用模式的剧变——从一次运行一个 Claude 到并行运行几百甚至上千个。

深度阐述
三个叠加因素

实际上只有很小比例的用户达到速率限制。问题出在三个因素的叠加：一是 Anthropic 曾短暂降低过峰值限制（已恢复并翻倍）；二是某些插件和集成消耗 token 的效率很低；三是最根本的变化——用户从运行一个 Claude 变成同时运行五个，再到现在每晚并行运行几百甚至上千个 Claude。

竞争与应对

面对 OpenAI Codex 的竞争，Boris 回应说增长从未像现在这样快，并宣布了三个应对措施：翻倍速率限制、增加每周配额、以及通过 Elon Musk 的 Colossus 基础设施上线新容量。这种增长「完全超出了我们最疯狂的预测」。

"Nowadays, I'm running maybe five at a time. And then every night I run like hundreds of Claudes at a time all in parallel. Hundreds, sometimes thousands." — "现在我同时运行大约五个。然后每天晚上我并行运行几百个 Claude。几百个，有时上千个。"
07

超越编程：从 Auto Mode 到并行智能体

36:03 - 41:48
核心观点

Claude Code 的路线图围绕三个大方向展开：提升智能、运行更长任务（auto mode）、以及并行运行更多智能体。未来的聊天机器人将从「问答」进化为「主动行动」。

深度阐述
Auto Mode：让 Claude 判断安全

以前的权限提示系统让用户每次都要点「允许」，导致「权限疲劳」——用户机械地点「始终允许」，反而可能漏掉真正危险的操作。auto mode 的解决方案是让另一个 Claude 来判断工具调用是否安全。它只看到部分上下文，加上多层安全检查，经过数千个基准测试验证，被证明比人工判断更安全。

聊天机器人的未来

Alex 提出了他对聊天机器人未来的构想：不再是「我提问、你回答」，而是「我提问、你主动提出帮我做某件事」。Boris 的回应耐人寻味——「智能体就是未来，我们正在尝试各种不同的实验，有些就是这样的。」

"Instead of being thoughtful about every prompt because we're showing people so many dialogues, they just kind of got fatigued... auto mode is the answer." — "与其让你对每个提示都深思熟虑——因为我们展示了太多对话框，人们只是疲劳了——auto mode 就是答案。"
08

Claude 指挥 Claude：个人杠杆率的爆炸

41:48 - 44:37
核心观点

Boris Cherny 已经不再直接写代码，甚至不再直接提示 Claude——他有一个 Claude 负责提示其他 Claude。但 Anthropic 仍在招聘 Salesforce 管理员，因为人的判断力仍是不可替代的瓶颈。

深度阐述
嵌套式工作方式

当 Alex 引用沃顿商学院教授 Ethan Malik 的话——「当 AI 实验室解散他们的前沿部署工程团队时，你就知道他们相信超级智能了」——Boris 的回答揭示了他日常工作的真实状态：他不写代码，他提示 Claude，实际上现在他主要让一个 Claude 去提示其他 Claude。这种层层嵌套的工作方式代表了一种新的「杠杆率」。现在 Anthropic 一个工程师的杠杆率「简直是疯狂的」，一半的商务团队用 Claude Code，另一半用 Co-work。

人仍然是驾驶者

但 Boris 也指出了一个关键点：即使 Salesforce 能被 AI 自动配置，也需要有人告诉 AI 去做这件事。「这个链条会越来越深——人要求 Claude，Claude 要求 Claude，Claude 要求 Claude——但最终你仍然需要人来驾驶。」

"I don't write code. I prompt Claude. And actually nowadays, mostly what I'm doing is I have a Claude that prompts other Claudes. So I don't even talk to Claude." — "我不写代码。我提示 Claude。实际上现在，我主要做的是让一个 Claude 去提示其他 Claude。所以我甚至不直接跟 Claude 对话。"
09

SaaS 末日：护城河的重新洗牌

44:37 - 49:26
核心观点

AI 智能体将削弱「转换成本」这类护城河，但「网络效应」和「规模经济」会变得更重要。SaaS 行业不会消亡，但护城河的相对价值将被重新定价。

深度阐述
升值的护城河

网络效应——谁在写代码不重要，你能用 Claude Code 几小时构建一个消息应用，但它仍然没用，因为你的朋友不在上面。规模经济——台积电的工艺流程让成本随规模下降，这种根本的经济力量不受 AI 影响。

贬值的护城河

转换成本——以前从供应商 A 切换到供应商 B 需要大量人力和数据迁移，现在你可以让 Claude 来做，而且它会越来越擅长。Boris 的建议是：作为一家公司，审视自己的护城河组合，思考哪些会在 AI 时代升值，哪些会贬值。

"If you want to switch from vendor A to vendor B, you can just ask Claude to do that. And Claude is going to get better and better over time at it." — "如果你想从供应商 A 切换到供应商 B，你可以让 Claude 来做。Claude 会在这方面越来越强。"
10

自我改进的 AI：一个正在发生的现实

49:26 - 51:54
核心观点

Claude Code 自 2024 年 11 月起已 100% 由自己编写。虽然目前仍需人类做提示，但 Claude 已开始自主生成产品改进想法——这正是通向自我改进循环的起点。

深度阐述
自我编写的现状

Anthropic 联合创始人 Jack Clark 预测到 2028 年模型开始自我改进的概率是 60%。Boris 指出一个事实：自 Opus 4.5 发布以来，Claude Code 已经 100% 由自己编写。但他做了重要的区分——仍然是一个人在做提示，Claude 开始为自己生成下一步要构建什么的想法，但这些想法不总是好的，大部分想法还是他生成的。

快速起飞的可能性

Alex 追问这是否就是「快速起飞」的场景。Boris 没有回避：「这是可能的，这就是 Anthropic 存在的原因。」他强调每一位工程师和研究员加入 Anthropic 的理由都是 AI 安全。「到了某个时候，这会改变。模型会改进，它会变成更多一种自我强化的循环。」

"100% of Claude Code is written using Claude Code. This has been the case since Opus 4.5." — "Claude Code 100% 是用 Claude Code 写的。从 Opus 4.5 以来就是这样。"
11

世界模型之争

51:54 - 54:45
核心观点

Yann LeCun 认为 LLM 没有世界模型因此无法构建可靠智能体。Boris 用实际产品效果反驳——Opus 4.7 能独立完成八张机票和五家酒店的预订，这本身就暗示了某种程度的规划和推理能力。

深度阐述
LeCun 的论点

Yann LeCun 的论点直截了当：「没有世界模型你就无法构建可靠的智能体系统。大语言模型没有世界模型。它们在采取行动之前无法预测其行为的后果。它们只是行动，接下来发生什么是别人的问题。」

Anthropic 的研究发现

Boris 指向了 Anthropic 的研究：模型展现出了「非常令人惊讶的行为」——它们能够规划、能够推理。最令他震撼的例子是写诗：当模型写下第一行时，内部研究显示它已经在思考最后一行了。「你教这东西预测下一个词，如果下一个词足够难，它就必须学会真正地提前规划。」这可能是对 LLM 能力涌现最简洁的解释之一。

"You teach this thing to predict the next word and somehow if the next word is hard enough, it has to learn to really plan ahead and it has to learn how to do all of this." — "你教这东西预测下一个词，如果下一个词足够难，它就必须学会真正地提前规划，就必须学会做所有这些事情。"
12

这是未来还是一场狂热？

54:45 - 57:10
核心观点

当医生、电工、木匠——而非工程师——开始用编程工具构建和出售产品时，市场本身已经给出了答案。

深度阐述
黑客松的证据

在 Opus 4.7 的黑客松中，获奖者包括一位医生、一位电工和一位木匠——他们都没有编程经验。更令人印象深刻的是，有人在一次黑客松中构建并出售了一家创业公司。最初 Claude Code 确实是为工程师设计的，但非技术人员很快找到了用它构建经济价值的方式。

跨越障碍的使用者

甚至在 Co-work 推出之前，非技术人员就在终端里安装 Claude Code。对很多人来说那是他们第一次使用终端。他们跳过重重障碍，只是因为这东西太有用了。Boris 说：「对我来说作为产品人，这是最终的市场测试——这东西有用吗？是否有很多人每天都在用，而且持续每天在用？答案是，是的，有很多人，而且还在不断增长。」

"People were jumping through hoops to use it because it was so useful." — "人们跳过重重障碍去使用它，因为它太有用了。"
