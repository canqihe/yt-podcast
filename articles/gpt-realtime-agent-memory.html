02

嘉宾介绍与"Dreaming"功能解析

00:09:15 - 00:16:35
核心观点

Anthropic 的"Dreaming"功能和 OpenAI 的"记忆源"功能标志着 AI 记忆系统的重大突破。

深度阐述
人类类比的启示

Richmond Alake（Oracle 开发者体验专家）详细解读了 Anthropic 刚刚推出的"Dreaming"功能。Richmond 指出，"Dreaming"这个命名非常巧妙，因为它借鉴了人类大脑的工作方式。人类做梦是大脑巩固记忆的重要机制——我们在白天经历的信息，通过睡眠中的"做梦"过程被整合、强化，同时"遗忘"不那么重要的信息。Anthropic 的 Dreaming 功能本质上在做同样的事情：整合记忆、解决冲突、提取模式，使 Claude 在下次交互时能够更快地提供相关信息。

计算资源优化的智慧

更重要的是，这一设计体现了计算资源的优化策略：Anthropic 一直以来都是计算约束的，如果能够用更少的 token 提供更高质量的响应，他们会采纳这个方案。Dreaming 将部分计算需求转移到非高峰时段（夜间），在用户使用的高峰时段提供更高效、更精准的服务。

OpenAI 的路径

与此同时，OpenAI 也改进了记忆功能，允许用户对记忆源进行"点赞"或"点踩"，通过人类反馈循环来改进记忆单元。这种强化机制能够改善 GPT 的个性化体验。

记忆研究的先驱者

00:15:21 - 00:24:33
核心观点

某些研究团队领先行业整整一年，正在定义智能体记忆的未来方向。

深度阐述
领先一年

Richmond 提到，Sarah 和 Charles（MEGPT 论文的作者）一年前就发表了"Sleep to Compute"论文，提出的概念与 Anthropic 的 Dreaming 惊人相似。这些研究者可能是"整整一年领先于整个领域"。

Simulacra 论文：里程碑式的研究

Stanford 的 Simulacra 论文（Generative Agents）是这个领域的重要里程碑。研究团队创建了 1000 个具有个性和记忆的 AI 智能体，将它们放在一个虚拟小镇中生活。令人震惊的是，这些智能体展现出了类似人类的行为模式：形成社交关系、策划生日派对、询问是否可以带朋友参加聚会。这些行为是"涌现"出来的，而非被预先编程的。Richmond 称这个论文为"Multi-Agent 之前的 Multi-Agent"，它奠定了今天许多记忆实现的基础工作。

人类反馈的争议

关于 OpenAI 采用人类反馈（点赞/点踩）的方式，Richmond 认为这只是短期解决方案。从长远来看，这种需要人类介入的反馈循环会很快消失——理想状态是系统完全自动化。但他也理解，对于服务数亿用户的前沿实验室来说，他们承担不起犯错的风险（如之前 OpenAI 因记忆问题不得不回滚的个性功能）。

持续学习 vs. 上下文学习：重量级辩论

00:28:19 - 00:33:27
核心观点

我们需要改变模型权重（持续学习），还是仅通过外部记忆系统（上下文学习）就能实现 AGI？

深度阐述
核心问题

这是 AI 领域最激烈的辩论之一。观众提问："梦境功能不就等于承认 Transformer 无法保持状态吗？我们加上 Passover 日志就称之为学习，这个领域什么时候会转向内存和计算融合的基底？"Richmond 承认这是"绝对正确的"——当前大多数智能体记忆解决方案并没有触及实际的模型权重和参数。但我们能在不改变模型内部状态的情况下实现我们想要的吗？

Dario Amodei 的观点

Richmond 提到，Dario Amodei（Anthropic CEO）曾在播客中表示：仅靠 LLM 的上下文学习能力，我们就能实现数万亿美元的经济价值。这意味着我们可能不需要持续学习范式。

Richmond 的立场

Richmond 的观点在不断"翻转"。他认为：模型权重可能就像汽车的引擎，但你还需要汽车本身（记忆、工具、装备）才能把马力传递到道路上；也许模型权重永远不够，你需要它周围的系统。他强调："唯一能确定的方式就是身处竞技场（in the arena）。"这正是 Oracle 正在做的事情——每天实验、测试、学习。

实时 LoRA：前沿探索

观众提到"实时 LoRA"——实时修改模型的一部分以更新它。Richmond 确认这是他们正在探索的方向之一，并预告"几个月内会有东西发布"。这展示了前沿企业在持续学习领域的积极探索。

05

记忆工程：从上下文到认知

00:36:16 - 01:07:08
核心观点

AI 应用从聊天机器人 → RAG → 自动化/自主性的演进，记忆工程是下一个关键战场。

深度阐述
AI 应用的成熟度阶段

Richmond 将 AI 应用的发展分为三个阶段：1. 聊天机器人阶段：LLM + 聊天界面；2. RAG 阶段：加入个性化/领域数据，但只是被动检索；3. 自动化/自主性阶段：智能体能够使用工具、做出决策、管理上下文窗口。大多数客户真正需要的是"自动化"（工作流程的自动化），而非"自主性"（让 AI 随意行动）。

上下文工程的重要性

随着对话越来越长，必须"工程化"上下文窗口中的信息。Richmond 详细解释了几种上下文工程技术：上下文窗口利用率（LLM 需要知道自己的容量限制）、压缩/减少（Claude 的自动压缩功能）、上下文卸载和检索（将信息转移到外部存储）。

记忆工程的崛起

Richmond 创造了"记忆工程（Memory Engineering）"这个术语。与上下文工程不同，记忆工程关注的是：工程化上下文窗口之外的信息、创建新信息、整合记忆、遗忘机制、增强记忆。这正是 Anthropic 的 Dreaming 和 OpenAI 的人类反馈在做的事情。

认知科学的借鉴

Richmond 强调借鉴人类记忆系统的重要性：程序记忆（技能、工具箱如 skills.md 文件）、情景记忆（有时间关联的对话记录）、语义记忆（事实知识）、共享记忆（多智能体系统的协调机制）。历史证明，从神经科学借鉴是成功的策略：Hubel 和 Wiesel 对猫视觉皮层的研究影响了卷积神经网络的发展；早期航空工程师从鸟类获得灵感设计飞机（尽管最初是"扑翼机"，但最终进化成了更快的喷气式飞机）。

Fox on the Run 的深刻评论

观众 Fox on the Run 指出："Hubel & Wisel 展示了连续的分层处理。我们采用了离散的 token 并称之为智能——基本上我们正在构建羽毛飞机。"Richmond 深表认同："我们仍在构建羽毛飞机"——但这可能就足够了。

Oracle 的实践：数据与实验

01:07:08 - 01:19:55
核心观点

Oracle 通过实际实验证明，工程化的智能体记忆可以保持稳定性能同时大幅降低 token 消耗。

深度阐述
关键实验

Richmond 展示了一个关键实验：运行 100 次对话迭代，结果显示：红色线（天真的智能体）token 消耗持续上升；绿色线（工程化记忆）token 消耗保持相对稳定。更令人印象深刻的是，使用 LLM 作为评判的结果显示：工程化记忆的响应质量优于或等同于天真的方法。

KV 缓存的权衡

进一步的实验显示：天真方法（无记忆工程）保持 KV 缓存，延迟最低；完全优化的方法延迟较高；折中方案在保持可比较延迟的同时实现记忆工程的优势。

一个笔记本，多种洞察

Richmond 展示的 Oracle AI 开发者中心笔记本包含：记忆工程实现代码、性能基准测试、LLM-as-a-judge 评估框架。

CAG 论文：前沿探索

观众询问"在会话开始时用整合记忆嵌入预填充 KV 缓存"的问题。Richmond 提到 CAG（Cache-Augmented Generation）论文，这种方法通过预计算并预填充 KV 缓存来避免 RAG，可以节省运营成本。Richmond 承认需要实验验证，预告会重新审视这个方法。

终极问题：智能体应该如何"遗忘"？

00:50:53 - 00:52:55
核心观点

学习如何"遗忘"是智能体记忆中最具创造性的部分。

深度阐述
深刻的问题

观众 Guy I5X 提出了一个深刻的问题："智能体应该如何决定遗忘什么？因为存储所有内容会产生检索噪声和系统漂移。"

Richmond 的回答

Richmond 的回答发人深省：神经科学研究表明，人类可能永远不会真正遗忘任何信息；大脑只是更善于在需要时"提供"相关信息。在计算领域，可以通过为记忆单元附加因素来实现遗忘机制：最近性（Recency）、相关性（Relevance）、重要性（Importance）。通过计算这些指标的加权值，系统可以决定信息的重要性，进而决定提供、降低重要性还是"遗忘"某些信息。

GenAI Agents 论文的实现

Simulacra 论文实现了一个简单的遗忘机制，即使是这样简单的实现也能达到非常好的性能水平。这证明了"遗忘"机制的重要性。
